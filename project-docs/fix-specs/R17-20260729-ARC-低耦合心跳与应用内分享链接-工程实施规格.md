## 2. 任务 A：客户端心跳（BUG-NET-001 / NET-01）

### 2.1 新增组件（首选）

| 文件 | 操作 | 职责 |
|---|---|---|
| `Client/clientheartbeat.h` | 新增 | `QObject` 心跳状态机接口 |
| `Client/clientheartbeat.cpp` | 新增 | 唯一 `QTimer` 调度、PING 构造、PONG 确认、连续超时计算 |
| `Client/Client.pro` | 最小修改 | 仅将以上两文件加入 `SOURCES`/`HEADERS` |

建议接口（可等价命名，但职责不能散入页面）：

```cpp
class ClientHeartbeat : public QObject {
    Q_OBJECT
public:
    explicit ClientHeartbeat(QObject *parent = nullptr);
    void start();
    void stop();
    void acknowledge();
signals:
    void sendHeartbeat();
    void connectionUnhealthy();
};
```

约束：间隔 30 秒；每个周期发送 PING 前将未确认数加 1；收到 PONG 时清零；达到 3 次才发 `connectionUnhealthy()`。`start()` 必须幂等，防止重复定时器；`stop()` 必须停止计时器并清零状态。

### 2.2 允许的既有接入点

| 文件 | 允许追加 | 禁止 |
|---|---|---|
| `Client/client.h/.cpp` | 增加 `ClientHeartbeat*` 成员；连接 `sendHeartbeat` 到一个只构造空 `HEARTBEAT_REQUEST` 并调用 `seedMsg()` 的槽；连接不健康信号到 `sorket.abort()`；连接 `QTcpSocket::disconnected` 至 `stop()` | 不改 `recvmsg()` 粘包逻辑、`seedMsg()` 所有权、登录/注销业务语义 |
| `Client/msghandler.h/.cpp` | 增加仅调用 `ClientHeartbeat::acknowledge()` 的 PONG 处理函数（或等价窄方法） | 不将 PONG 显示为 UI 消息、不访问 File/Friend/Chat |
| `Client/client.cpp::handlMsg()` | 仅新增 `ENUM_MSG_TYPE_HEARTBEAT_RESPOND` case | 不改变其他 case 顺序或行为 |
| `Server/mytcpsocket.cpp::handlMsg()` | 仅新增 `ENUM_MSG_TYPE_HEARTBEAT_REQUEST` case，构造空 `HEARTBEAT_RESPOND` 返回 | 不改 `seedMsg()`、`sendAndRelease()`、`recvmsg()`、下载流或断开清理 |

启动时机：只在 `LOGIN_RESPOND` 的成功分支、主界面显示后启动。停止时机：socket `disconnected`、注销请求发起前、Client 析构。不要改 `MyTcpServer`，不要加服务器扫描 QTimer，服务端也不需要 DB 写入。

### 2.3 验证（工程师自检，非最终测试）

1. `qmake Client.pro && make` 与 `qmake Server.pro && make` 均成功。
2. 两端协议头 `HEARTBEAT_REQUEST=50`、`HEARTBEAT_RESPOND=51` 一字不差；**不得改动 1~53 任何已有数值**。
3. 登录后日志（不含敏感数据）可证实每 30 秒仅发送一条 PING，服务端回一条 PONG，连续至少 3 轮无重复 timer。
4. 断开网络或停止服务端后，第 3 个未确认周期才调用 `abort()`；原 `disconnected → clientOffLine()` 清理仍发生。
5. 登录、好友列表、文件列表、下载和既有好友分享不因心跳出现新的 UI 行为或协议变化。

## 3. 任务 B：应用内分享链接（FILE-11）

### 3.1 新增组件与数据表

| 文件 | 操作 | 职责 |
|---|---|---|
| `Server/sharelinkservice.h/.cpp` | 新增 | token 生成、SHA-256 hash、创建/解析编排、路径校验；不依赖好友分享函数 |
| `Client/sharelinkdialog.h/.cpp/.ui` | 新增 | 显示/复制链接、输入并解析链接的独立 UI |
| `Client/Client.pro` | 最小修改 | 注册新增分享链接文件和 `.ui` |
| `Server/Server.pro` | 最小修改 | 注册 `sharelinkservice` |
| `Server/operatedb.h/.cpp` | 最小修改 | 仅追加 `share_link` 建表和必要的增/查窄接口，所有 SQL 必须 `prepare()` + `bindValue()` |

数据库表（允许等价字段类型；不得迁移或修改已有业务表）：

```sql
CREATE TABLE IF NOT EXISTS share_link (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  token_hash CHAR(64) NOT NULL UNIQUE,
  owner_name VARCHAR(255) NOT NULL,
  relative_path VARCHAR(1024) NOT NULL,
  expire_time DATETIME NOT NULL,
  revoked TINYINT NOT NULL DEFAULT 0,
  created_at DATETIME NOT NULL
);
```

原始 token 必须以 `QRandomGenerator::system()` 生成至少 16 个随机字节、URL-safe 编码；数据库仅保存 SHA-256 hex hash。不得将完整 token 写入 `qDebug()`、报错文字、DB 或测试归档。

### 3.2 协议与分发

两端 `protocol.h` 已有创建链接 `52/53`，只允许在末尾追加：

```cpp
ENUM_MSG_TYPE_RESOLVE_PUBLINK_REQUEST = 54,
ENUM_MSG_TYPE_RESOLVE_PUBLINK_RESPOND = 55,
```

必须同时在以下精确接入点追加分发：

- `Client/client.cpp::handlMsg()`：`CREATE_PUBLINK_RESPOND`、`RESOLVE_PUBLINK_RESPOND`；
- `Server/mytcpsocket.cpp::handlMsg()`：`CREATE_PUBLINK_REQUEST`、`RESOLVE_PUBLINK_REQUEST`；
- `Client/msghandler.*`、`Server/msghandler.*`：只增加各自链接请求/响应的窄处理入口。

PDU 契约以 `project-docs/interfaces.md §1.3/§1.4` 为准：创建请求的文件相对路径与解析请求 token 放在 `caMsg`；成功创建的链接放在响应 `caMsg`；解析成功的响应仅返回安全元数据，随后启动**既有**下载流。不要重定义 40~43 下载协议，不要在 `sharefilemove()` 内添加链接逻辑。

### 3.3 权限与路径规则（硬性）

1. 创建者身份使用服务端 socket 已登录的 `m_strLoginName`，**不信任客户端提交 owner/user 名称**。
2. 只允许分享当前 owner 根目录内的存在的普通文件；以 owner 根目录为基准保存相对路径。
3. 创建和解析均以 `canonicalFilePath()` + owner root canonical 前缀复核；目标不存在、目录、路径逃逸、过期或 `revoked=1` 均返回失败。
4. 解析者必须已登录；本期不建立好友关系、不修改源文件、不复制文件、不更改文件列表、不改用户/好友表。
5. 默认过期时间固定为创建后 24 小时；UI 首期不暴露可配置时长。后续产品需求再扩展密码、撤销界面、访问计数或匿名访问。

### 3.4 UI 最小接入

`Client/file.h/.cpp` 只允许追加两个窄入口：从当前选中**普通文件**打开创建链接对话框；从独立对话框解析链接。不得重写 `file.ui` 或 `sharefile.ui`；若无法以 Designer 安全追加按钮，可用现有菜单/动作的最小追加并在变更摘要说明。
