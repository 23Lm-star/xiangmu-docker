# 非功能要求

> 生成依据：代码实现、已知文档、代码审查发现
> 状态：初版

---

## 1. 性能

| 要求 | 当前实现 | 评估 |
|------|----------|------|
| 并发连接数 | QThreadPool max=8；Socket I/O 实际在主线程事件循环处理 | 瓶颈：`tcpsocketlist` 无锁，高并发下可能竞态 |
| 上传并发 | 单客户端单线程 `Uploader`，独立 QThread | 合理 |
| 数据库连接 | 连接池按线程隔离，每线程上限 8 连接 | 合理，但缺少断线重连 |
| 内存分配 | 自研三级内存池（TCMalloc 风格），高频小对象分配走 TLS 无锁路径 | 优于通用 malloc |
| 文件操作 | 分享使用 `QFile::copy()` 同步复制，大文件阻塞 | 待优化（中等风险） |
| 下载文件 | 服务端 `QFile::readAll()` 一次性读入内存 | 大文件会耗尽内存（风险） |

## 2. 安全

| 风险 | 当前状态 | 严重度 | 建议 |
|------|----------|--------|------|
| SQL 注入 | 全部使用 `QString::arg` 字符串拼接 | **严重** | 迁移到预编译 `QSqlQuery` 与绑定参数 |
| 密码存储 | MD5 无盐 | **一般** | 迁移到 bcrypt/scrypt/Argon2 或加盐 SHA-256 |
| 密码传输 | 客户端 MD5 后传输（非明文） | 可接受（临时） | 后续应支持 TLS 传输层加密 |
| 路径穿越 | 下载路径使用 `QFileInfo::canonicalFilePath()` 前缀校验 | 已防护 | 可靠 |
| 验证码 | 服务端生成，60 秒有效，客户端输入比对 | 可接受 | 无防暴力破解限制 |
| 配置文件 | 数据库密码硬编码在 `Server/operatedb.cpp:285` | **严重** | 应外部化配置或加密 |
| 应用内分享链接 | 规划中 | **严重** | token 至少 128 bit 系统随机值；仅存 SHA-256 hash；创建和解析均强制 owner 根目录 canonical 校验；不得写入日志。 |

## 3. 可用性

| 要求 | 当前状态 |
|------|----------|
| 启动顺序 | 必须先启动 Server，再启动 Client |
| 网络断开 | 无自动重连机制；`QTcpSocket::disconnected` 仅触发下线清理 |
| 假死连接 | 规划：ClientHeartbeat 每 30 秒 PING；连续 3 次未 PONG 才中止连接，避免单次抖动误断；不改动业务模块。 |
| 错误提示 | MySQL 连接失败时仅打印 qDebug，无用户可见提示 |

## 6. 数据一致性

| 场景 | 当前处理 |
|------|----------|
| 聊天消息持久化 | 在线消息实时标记送达；离线消息上线后拉取并标记 |
| 好友关系 | 双向存储（A→B 和 B→A 分别 INSERT） |
| 断点续传 | 服务端校验 offset 连续性，不连续则失败 |
| 多客户端同一用户 | 无限制，允许多处登录（可能互相覆盖在线状态） |

## 7. 约束清单

| 约束 | 说明 |
|------|------|
| 最大对象大小（内存池） | 256 KB |
| 页大小（内存池） | 8 KB（`PageShift=13`） |
| 线程池上限 | 8 线程 |
| 数据库每线程连接上限 | 8 |
| 上传分块大小 | `clamp(ceil(size/1024), 64 KiB, 1 MiB)`（REQ-EXT-TRANSFER-003；旧客户端 4 KB 形态仍兼容） |
| 上传数据通道单包上限 | 1 MiB + 4 KB（`MAX_UPLOAD_DATA_PDU_SIZE`，仅 31 生效；其余入站报文 16 KB 不变） |
| 用户名最大长度 | 31 字节（UTF-8） |
| 固定参数区 | `caData[64]`，超出部分需走 `caMsg` |
