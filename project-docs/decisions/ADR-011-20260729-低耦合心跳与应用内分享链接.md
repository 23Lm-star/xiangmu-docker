# ADR-011：低耦合客户端心跳与应用内分享链接

> 日期：2026-07-29  
> 裁决人：项目架构师  
> 关联需求：`EXP-NET-01`、`EXP-BUS-03`；关联缺陷：`BUG-NET-001`  
> 前置条件：`ADR-010-20260728-功能基线恢复.md` 的协议编号与既有功能恢复基线保持不变。

## 1. 已确认事实

1. 两端 `protocol.h` 已一致保留：心跳 `50/51`、创建外链 `52/53`；但没有任何业务分发或定时器实现。
2. 现有好友文件分享（`SHAREFILE_*`，33~37）是“在线好友确认后复制文件”的独立链路，不能复用为链接分享，否则会改变好友分享的确认、复制和通知语义。
3. 系统只有 Qt TCP Client/Server，当前没有 HTTP 服务、浏览器路由或 URL scheme 注册。因此不能将本期链接宣称为可由浏览器匿名访问的公网下载 URL。
4. `MyTcpSocket::seedMsg()`、`sendAndRelease()`、下载流、好友转发和现有断开清理路径是已验证保护区，禁止为本需求改动。
5. `Client` 已拥有唯一 `QTcpSocket`，现有登录成功和响应分发位置可作为必要接入点；`Client.pro`/`Server.pro` 使用 qmake。

## 2. 决策

### 2.1 心跳：客户端单实例、请求—响应、仅连接健康检测

采用新增 `ClientHeartbeat`（`QObject`）组件，由 `Client` 唯一持有；不让任何页面、文件模块、好友模块或聊天模块创建定时器。

- 登录响应成功后才启动；未登录、断开、注销请求发起时停止。
- 每 30 秒发送一个空 PDU：`ENUM_MSG_TYPE_HEARTBEAT_REQUEST=50`。
- 服务端 `MyTcpSocket::handlMsg()` 仅追加一个 case，立即构造空 `HEARTBEAT_RESPOND=51` 返回；不访问 DB、不改在线状态、不触发好友/聊天/文件逻辑。
- 客户端收到 PONG 时只调用 `ClientHeartbeat::acknowledge()`；连续 3 个周期未确认时，组件发出 `connectionUnhealthy()`，由 `Client` 调用 `sorket.abort()`，复用现有 `disconnected → clientOffLine()` 清理链路。
- 任意正常业务响应也只允许作为可选“活跃观察”重置未响应计数；本期为了行为可预测，**不以业务包替代 PONG**。
- 不引入服务端全局扫描定时器、`MyTcpServer` 成员、数据库字段或表；避免与连接列表锁和多端 `online` 语义耦合。

### 2.2 分享链接：认证的应用内访问凭证，不改变好友分享和原资源权限

本期“分享链接”定义为可复制、可粘贴的应用内链接：

```
cloud-disk://share/<opaque-token>
```

访问者必须已登录本系统。它不是匿名浏览器 URL，也不自动公开文件。

- 创建链接只读校验“当前登录用户的根目录下存在该普通文件”，不得接受任意绝对路径；不得复用旧 `sharefilemove()`。
- 链接只授予该文件的下载读取能力；不改变源文件、不修改 `friend`、`user_info` 或既有文件列表/下载接口的默认权限。
- 新增独立 `share_link` 表，仅新增不迁移既有表。至少保存：`token_hash`（唯一）、`owner_name`、`relative_path`、`expire_time`、`revoked`、`created_at`。数据库绝不存原始 token。
- token 使用 `QRandomGenerator::system()` 生成至少 128 bit 随机字节，经 URL-safe 编码；数据库以 SHA-256(token) 查询。日志、错误提示、qDebug 不得打印完整 token。
- 协议追加（两端同值）：`RESOLVE_PUBLINK_REQUEST=54`、`RESOLVE_PUBLINK_RESPOND=55`。52/53 仅负责创建；54/55 负责经 token 校验并返回受限文件元数据，随后复用**现有下载流启动机制**传输数据，而非复制/改写下载协议。
- 首期不支持匿名访问、密码、下载次数限制、链接管理列表与撤销 UI；撤销/过期管理列为后续需求，不能伪装为本期已实现能力。

## 3. 低耦合边界

| 类别 | 允许的最小修改 | 明确禁止 |
|---|---|---|
| 协议 | 两端 `protocol.h` 同步新增 54/55，并在 `interfaces.md` 登记 | 重排或改写 1~53 的既有值 |
| 心跳 | 新增 `ClientHeartbeat`；`Client` 生命周期/分发接入各少量追加；Server `MyTcpSocket::handlMsg()` 一个 case | 修改任何业务模块、`MyTcpServer`、DB、`seedMsg()`、下载流 |
| 分享链接 | 新增 `ShareLinkDialog`、`ShareLinkService`、`share_link` 表和窄 `OperateDB` 方法；必要的 PDU 分发 case | 修改既有好友分享 33~37、改变文件默认访问控制、通过路径直接复制/移动 |
| UI | File 页面仅追加“创建链接”“打开链接”入口；新对话框承载所有新 UI | 改动已有按钮槽语义、重写 `file.ui`/`sharefile.ui`、改好友分享界面流程 |

## 4. 风险与裁决

| 风险 | 等级 | 裁决/缓解 |
|---|---|---|
| “链接”被误解为浏览器匿名公网 URL | 严重（范围误解） | 本期明确为认证应用内链接；若用户要公网匿名访问，必须先新建 HTTP/鉴权边界 ADR，禁止临时暴露 TCP 协议。 |
| token 泄漏导致未授权下载 | 严重 | 仅存 hash、不记录原 token、随机源为系统级、过期校验；测试不得把真实 token 写入报告。 |
| 路径穿越/越权读取 | 严重 | 创建时转为 owner 根目录内的相对路径；解析时再次以 canonical 父目录/文件路径验证，禁止信任客户端路径。 |
| 心跳干扰业务连接 | 一般 | 单例计时器、登录后启动、空 PDU、独立 PONG 分发；3 次阈值才中止，断开仍走既有清理。 |
| 并发文件删除后链接失效 | 一般 | 解析时检查实际文件；不存在即返回失败，不影响原文件删除流程。 |

## 5. 分阶段与质量门禁

必须按两个独立提交执行：

1. **提交 A：心跳。** 编译 + 静态审查 + 动态验证通过后，才可开始分享链接。
2. **提交 B：分享链接。** 编译 + 静态审查 + 动态验证通过后，方可提交测试师。

任一步需要修改保护区或既有业务语义，工程师必须停止，不得自行扩大范围。
