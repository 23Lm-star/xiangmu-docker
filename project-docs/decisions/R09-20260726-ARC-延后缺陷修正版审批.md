# 架构师裁决记录：延后缺陷修正版与二次审查结果审批

**时间**：2026-07-26
**裁决人**：项目架构师
**主题**：审批 BUG-DB-003、BUG-SEC-001、BUG-NET-001 修正版方案及 BUG-FILE-002-R1 补充修复方向

## 1. BUG-FILE-002-R1（目标路径校验缺陷）
* **审查结论**：Bug 查找师提出的语义缺陷判定完全正确。`canonicalFilePath()` 在文件不存在时返回空字符串，导致合法的文件移动操作被拒绝。
* **架构师裁决**：**批准补充修复**。
* **执行要求**：
  * 改为校验目标父目录的规范路径 `dstInfo.dir().canonicalPath()`。
  * 保持源路径校验逻辑不变。
* **状态变更**：重新打开 -> 修复中。

## 2. BUG-DB-003（数据库断线重连）
* **方案审查**：采用方案 A（懒重连 + 定时健康检查）。通过 `OperateDB`（QObject）持有定时器并定期调用 `DatabaseConnectionPool::healthCheck()`，完美规避了原方案中非 QObject 类直接使用 QTimer 的问题；同时保留 `acquire()` 时的指数退避重连作为兜底。
* **架构师裁决**：**批准方案**。
* **执行要求**：
  * 按 fix-spec 实现双重保障机制。
  * 确保健康检查对性能影响极小（仅执行 `SELECT 1`）。
* **状态变更**：延后 -> 修复中。

## 3. BUG-SEC-001（密码无盐 MD5）
* **方案审查**：透明迁移策略设计得非常巧妙。服务端加盐 SHA-256、通过 Client 发送的 MD5 进一步 Hash 的方案，实现了零客户端改动。针对旧用户的无缝平滑升级（检测到 salt 为空时自动重算并更新 DB）既兼顾了历史数据，又提升了未来的安全性。
* **架构师裁决**：**批准方案**。
* **执行要求**：
  * 数据库的 `ALTER TABLE` 语句需由工程师手工或通过脚本在测试库和最终库执行。
  * 确保更新逻辑与登录逻辑在同一个方法内完成，保持业务连贯。
* **状态变更**：延后 -> 修复中。

## 4. BUG-NET-001（应用层心跳机制）
* **方案审查**：方案严格遵循了“服务端单向驱动”的裁决。服务端发 Request，客户端回 Respond，服务端在登录成功后启动心跳检测，最大容忍 3 次未响应断开连接。逻辑清晰且没有重复发包问题。
* **架构师裁决**：**批准方案**。
* **执行要求**：
  * 确保 `m_heartbeatTimer` 的生命周期与 `MyTcpSocket` 一致。
  * 确保未登录的连接不会启动心跳检测。
* **状态变更**：延后 -> 修复中。
