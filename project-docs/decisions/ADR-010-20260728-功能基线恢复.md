# ADR-010：错误 Git 回退后的功能基线恢复

> 日期：2026-07-28  
> 关联：`BUG-ARC-RECOVERY-001`、`REQ-AUTH-001`、`EXP-NET-01`、`EXP-BUS-03`

## 事实

当前 HEAD 为 `d6c579c`。Git reflog 证明历史功能提交随后被 `git reset HEAD~1` 回退。历史提交 `149a087`/`c6a472c` 含注销、心跳、外链相关实现，但也混入危险回退：Server PDU 将 `memfree()` 改为 `free()`、`seedMsg()` 不释放响应 PDU、好友转发绕过 `sendAddFriendAndRelease()`、以及 QRC 资源删除。

当前基线仍保持 SQL 参数化、连接列表锁、流式下载、PDU 三层防护、PDU 正确释放等既有修复。

## 决策

1. 禁止 `reset`、`reset --hard`、`checkout .`、`restore .`、`commit --amend` 和整体 `cherry-pick` / 整文件覆盖历史提交。
2. 在独立恢复分支，先使 Client 与 Server 协议枚举显式且完全一致：
   - 下载 `40..43`；验证码 `44..45`；用户信息请求/响应 `46..47`；注销 `48..49`；心跳 `50..51`；外链创建 `52..53`。
3. 按单独提交恢复：协议兼容 → 安全注销 → 静态审查与动态回归 → 心跳 → 外链。
4. 禁止修改 `MyTcpSocket::seedMsg()`、`sendAndRelease()`、下载流、好友转发、既有 socket 清理路径；Server PDU 必须保持 `memfree()`。

## 结果

恢复工作必须用最小差异、一个功能一个提交、一次提交一轮审查与回归的方式执行。
