# Bug 查找师修复解决方案

> 本目录存放 Bug 查找师对**复杂问题**的修复解决方案。
>
> 当静态审查报告中无法完整清晰地叙述修复流程时，Bug 查找师在此补充详细方案说明。
> **简单问题不需要创建此文件**，直接在审查报告或交接指令中说明即可。

---

## 目录结构

```text
bug-fix-slove/
  ├── README.md                  ← 本文件
  └── (解决方案文件 *.md)
```

## 文件命名规则

所有文件使用批次命名规则，格式为：

```
[批次前缀]-[YYYYMMDD]-[Agent缩写]-[缺陷编号]-[用途说明].md
```

示例：`R01-20260724-REV-BUG-ARC-PROTOCOL-001-枚举冲突解决方案.md`

详见 `agent-collaboration-rules.md` 第十三节（文档批次命名规则）。

## 创建条件

建议创建 `bug-fix-slove/` 文件的情况：

- 修复涉及多个文件、多个模块的修改
- 修复涉及架构权衡（性能 vs 可维护性等）
- 修复需要分多个步骤、有中间状态的
- 修复有多个可选方案，需要说明选择理由的

**不需要创建**的情况（直接在下游交接指令中说明即可）：

- 单行改动（拼写修正、命名修正）
- 简单的参数调整
- 显而易见的修复

## 内容模板

```markdown
# 修复方案：[缺陷标题]

## 缺陷编号
BUG-XXX-XXX-XXX

## 问题原因
[分析根本原因]

## 修复方案
[描述修复方案，包括：]
- 修改哪些文件
- 修改什么内容
- 为什么这样修改

## 可选方案
[如果有多个方案，说明各方案的优缺点和选择理由]

## 影响范围
[影响哪些模块、是否需要同步修改两端]

## 验证建议
[建议如何验证修复的正确性]
```
