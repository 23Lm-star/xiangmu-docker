# 缺陷二次审查报告 - BUG-REV-AUTH-004

> 审查时间：2026-07-29
> 审查员：Bug 查找师
> 目标：确认服务端注销功能中的越界读取内存污染问题已修复

## 第一层：变更审查
- 目标：检查 `Server/msghandler.cpp` 中 `logoff` 函数处理 `pdu->caData` 的逻辑。
- 结论：工程师已将原有不安全的 `memcpy` 调用更换为使用项目中已经封装好的安全解析函数 `fixedString()`。

## 第二层：逻辑与副作用分析
- `fixedString` 函数内置了对空终止符的处理，如果在指定的长度 (`maxLen`) 内找到 `\0`，则在此处截断，避免了后续读取越界内存区域的可能。
- `userName` 与 `userPwd` 皆以期望的 32 字节边界定长解析。
- 从解析得到的 `QString` 直接转为 `UTF-8` `constData()` 传入数据库查询层，不再存在越界粘连和导致数据库 SQL `WHERE` 条件不匹配或产生报错日志的风险。

## 第三层：结果验证
- 根据用户提供的信息，二进制文件构建成功。
- 在对 `Server/msghandler.cpp` 内容的静态代码检查中，明确看到改用了 `fixedString()`，没有残留基于旧逻辑的不安全代码。
- 考虑到功能本身也是基于相同的底层逻辑实现（如登录、注册也是使用 `fixedString`）安全地将 PDU 的前 64 字节切分为用户名和密码，所以此修复也是具有一致性的。

## 结论
修复方式符合规范，从根源规避了由 `char` 数组未加 `\0` 引起的潜在内存越界/字符串污染的隐患。未发现伴随修复带来的其他副作用。
**判定：** 二次审查通过。

BUG-REV-AUTH-004 状态更新为 **已修复**。
