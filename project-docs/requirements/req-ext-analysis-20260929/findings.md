# 扩展需求分析发现

- 项目当前为 Qt 5.14.2 C/S 桌面云盘 + 聊天，协议为自定义 PDU，协议头文件是冻结路径。
- 当前已实现好友和一对一聊天；数据库初始化脚本只声明 `user_info`、`friend`，不能直接假定群表或文件资产表已存在。
- 当前上传是单文件、4096 字节、连续 offset、逐块 ACK；上传会话仍围绕用户路径和现有文件模型。
- 群需求中的角色校验、消息持久化、成员变化广播、离线消息和未读计数均需要服务端事实源与事务边界。
- `group_member(group_id,user_id)` 的永久联合唯一约束与离开后再次入群/历史审计存在冲突，需要可重激活的成员记录或独立历史表。
- `group_message.seq` 不能依赖普通自增列；必须定义按群原子分配、重试幂等和并发锁定策略。
- `file_object/user_file` 是秒传和后续引用式分享的前置模型；直接在现有路径上增加 Hash 检查会形成两套来源事实。
- 现有路线图已经建议 P0 会话与统一鉴权、P1 任务化传输、P2 文件资产层、P3 协作与可靠消息；本次拆分沿用该依赖方向并收窄首期范围。
