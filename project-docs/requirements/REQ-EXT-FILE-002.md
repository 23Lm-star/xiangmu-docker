# REQ-EXT-FILE-002 顺序上传秒传与去重

## 1. 分支信息

- 分支：`codex/req-ext-file-002-fast-upload`（快速上传与去重）
- 层级：LARGE；触碰冻结协议、上传状态机和文件资产事务
- 依赖：`REQ-EXT-SEC-001`、`REQ-EXT-FILE-001`

## 2. 目标

在不改变现有连续 offset、4096 字节顺序 ACK 基线的前提下，增加 Hash 预检查和物理对象复用。命中时直接创建逻辑文件条目；未命中时继续现有断点上传，完成后由服务端复算并转正。

## 3. 协议要求

- 新增请求/响应类型只追加旧枚举之后，不能重编号；两端协议头必须保持一致并通过自动校验。
- 初始化请求至少包含目标目录标识、文件大小、客户端 SHA-256 预摘要、展示名和客户端请求唯一标识；服务端响应包含命中结果、逻辑文件标识或上传会话标识。
- 不把可变长度文件名和路径塞进固定 `caData[64]`（固定控制区）；使用版本化长度字段和 `caMsg`（可变载荷区），服务端限制总长度。
- 现有上传数据包继续携带会话标识和连续 offset；未完成会话不能被视为正式对象。

## 4. 服务端流程

1. 依据服务端主体和授权目录解析目标位置，校验大小和摘要格式。
2. 先查找相同摘要/大小的有效 `file_object`；命中后在事务中创建 `user_file`，不读取客户端物理路径、不复制物理文件。
3. 未命中则创建临时上传会话，沿用顺序分块写盘和 ACK；会话超时可清理但不能删除已有对象。
4. 收齐后服务端重新计算 SHA-256 和大小；不一致则删除临时文件并返回校验失败。
5. 校验成功后在事务中创建/复用对象、逻辑条目和引用计数；同名规则由服务端统一生成。

## 5. 验收标准

1. 已存在对象命中时网络上不传输文件正文，逻辑条目可立即读取。
2. 同内容不同名只保存一个物理对象；同名不同内容得到稳定且不冲突的展示名。
3. 伪造客户端摘要、大小、路径或上传者不能命中无权对象；服务端复算失败不转正。
4. 两个并发相同文件上传不会生成两个有效物理对象，失败的一方可幂等复用已转正对象。
5. 中断上传可按会话继续；过期临时会话清理不影响已完成对象和现有用户文件。
6. 现有上传、下载、断点续传、分享和路径防护回归通过，内存使用不因 Hash 计算一次性读入超大文件。

## 6. 不包含与停止条件

本分支不实现动态分片、乱序并行分片、多文件任务中心、对象存储或独立文件服务。若协议兼容性、服务端复算或对象唯一性无法被独立测试证明，禁止进入群文件分支。
