# REQ-EXT-GROUP-001 群生命周期与成员关系

## 1. 分支信息

- 分支：`codex/req-ext-group-001-membership`（群生命周期与成员关系）
- 层级：LARGE；触碰 PDU、数据库和服务端权限
- 依赖：`REQ-EXT-SEC-001`
- 后继：`REQ-EXT-GROUP-002`

## 2. 目标

提供可审计的群创建、邀请、接受/拒绝、退出、移除、角色和成员列表能力，形成后续群消息与群文件使用的唯一成员事实源。

## 3. 数据与状态

- `group_info`（群基本信息）：`group_id`、名称、创建者、状态、创建时间、版本号。
- `group_member`（当前成员）：群标识、用户标识、角色、成员状态、加入时间、更新时间；离开后允许重激活，不得因历史记录无法重入。
- `group_invitation`（群邀请）：独立邀请标识、群、邀请人、目标人、状态、过期时间、创建/处理时间、幂等键。
- 状态转换必须拒绝重复接受、已过期接受、已移除成员操作和越权角色变更。

## 4. 权限规则

- 群主：全部成员管理、角色管理、群资料和解散操作；
- 管理员：邀请、移除普通成员和查看成员；不能移除群主或其他管理员，不能转让/解散群；
- 普通成员：查看群资料和成员、主动退出；
- 所有规则在服务端执行，客户端按钮只负责展示。

## 5. 协议与实现要求

- 新 PDU 枚举只追加到现有 59 之后，禁止重排旧编号；
- 载荷必须带版本、长度和请求唯一标识，避免直接传输带编译器填充的 C++ 结构体；
- 创建群和创建群主成员在一个数据库事务中完成；接受邀请和激活成员在一个事务中完成；
- 成员变化向在线成员发送事件，离线成员登录后可查询未处理邀请和最新群摘要。

## 6. 验收标准

1. 创建群失败时不残留群或孤立群主记录。
2. 同一待处理邀请重复请求只产生一个逻辑结果；拒绝/过期后可以按规则重新邀请。
3. 群主转让、管理员任免、退出、移除和重入满足角色限制，越权请求全部拒绝。
4. 成员列表只返回当前有权查看的群，不能通过修改群标识读取其他群。
5. 两个并发接受/移除请求最终状态唯一，数据库无重复有效成员。
6. 新旧客户端至少能完成登录、好友、一对一聊天和旧文件业务回归。

## 7. 不包含与停止条件

本分支不实现群消息正文、群文件上传和群公告。若成员状态无法在并发下保持唯一，或协议新旧版本无法明确拒绝未知类型，停止进入后继分支。
