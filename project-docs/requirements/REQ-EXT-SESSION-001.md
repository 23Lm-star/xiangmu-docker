# REQ-EXT-SESSION-001 唯一登录（登录版本失效与踢下线）

## 1. 分支信息

- 分支：`claude/req-ext-session-001-unique-login`
- 层级：LARGE；触碰鉴权/会话架构与生产数据契约
- 基线：master@`ccfd5de`（含 SEC-001 统一鉴权入口、AUTH-002 加盐登录、FS-003 路径沙箱）
- 并行在途：REQ-EXT-FILE-001（独立测试节点，未合并）——冲突面核查见任务记录

## 2. 目标

同一账号只允许最后一次登录存活。每次登录写入登录记录并把该用户的新登录版本号持久化；该用户更早登录留下的连接，其后续任何业务请求在服务端处理前被版本校验拦截，服务端直接切断连接。

## 3. 数据模型

- `user_info` 追加列 `login_version`（整型，默认 0）：该用户最新登录版本号，登录成功时在事务内原子 +1，禁止读后加一。
- 新表 `login_record`：用户名、客户端唯一信息、登录版本号、登录时间；每次成功登录插入一行；`(username, login_version)` 建索引。
- 迁移采用独立 SQL 文件（先例：`Server/migrate_add_password_salt.sql`）。

## 4. 处理流程

1. 客户端在登录请求中携带持久化的客户端唯一标识；标识缺失仍可登录，登录记录按空值存储。
2. 凭据校验通过后：同一事务内 `login_version` 原子 +1、写入 `login_record`、版本号绑定到当前连接（连接级状态，服务端权威，不依赖客户端每请求回传）。
3. 登录成功时，服务端关闭该用户名下除本连接外的全部存量连接。
4. 统一鉴权入口在认证检查之后追加版本校验：白名单（注册/登录/验证码/心跳）之外的每个请求，处理前比对连接绑定版本与该用户最新登录版本；不一致 → 拒绝处理并直接断开连接。
5. 旧连接断开触发的下线处理必须校验"断开方仍是权威会话"，否则不得清除在线状态（防误清新会话）。

## 5. 协议边界（主人 2026-09-30 批准）

零协议改动：客户端标识走登录 PDU 现有附加负载；版本号连接级绑定；踢线不断连通知不新增 PDU 枚举。**两个 `protocol.h` 全程零命中**（frozen_paths）。

## 6. 验收标准

1. A 设备登录后 B 设备同账号登录，A 的下一次业务请求被拒绝且连接被服务端关闭；B 正常。
2. 每次成功登录 `login_record` 恰增一行，`user_info.login_version` 等于该行版本号。
3. 版本校验先于一切业务处理；白名单四类请求不受版本校验影响。
4. 并发双登录版本号不重复、不倒退（数据库原子性证据）。
5. 被踢旧连接断开不误清新会话在线状态（竞态断言）。
6. 客户端标识缺失的登录仍然成功并记录。
7. 回归：SEC-001 全量 e2e、一对一聊天、离线消息、文件功能通过；分支 diff 对两 `protocol.h` 零命中。

## 7. 不包含与停止条件

不含踢线原因通知协议、多端登录白名单、异地提醒推送；不触碰 FILE-001 的上传/资产面与 GROUP 系列表域；开发启动条件与 schema 版本机制适配规则见任务记录，无法满足时开发节点只报告不即兴扩面。
