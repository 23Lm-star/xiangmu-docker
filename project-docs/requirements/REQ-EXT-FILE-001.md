# REQ-EXT-FILE-001 文件资产与内容寻址

## 1. 分支信息

- 分支：`codex/req-ext-file-001-file-assets`（文件资产模型）
- 层级：LARGE；触碰文件存储、数据库迁移和权限边界
- 依赖：`REQ-EXT-SEC-001`
- 后继：`REQ-EXT-FILE-002`、`REQ-EXT-GROUP-003`

## 2. 目标

把物理文件内容和用户看到的逻辑文件条目分离，为秒传、去重、引用式分享和群文件目录提供稳定资产 ID（标识）。迁移期间继续兼容现有用户路径，不能直接删除旧目录。

## 3. 数据模型

- `file_object`（物理内容对象）：`object_id`、SHA-256 内容摘要、大小、服务端存储路径、引用计数、状态、创建时间。
- `user_file`（用户逻辑条目）：`file_id`、用户/权限主体、父目录标识、展示名、对象标识、状态、创建/更新时间。
- `upload_session`（上传会话）：用户、目标目录、期望大小、客户端摘要、临时路径、已确认 offset、状态、过期时间。
- 物理对象的路径和状态只能由服务端生成；客户端只能提交预检查元数据。

## 4. 一致性要求

- 对象命中、逻辑条目创建和引用计数更新必须在同一事务内完成；
- 删除逻辑条目只减少引用，引用归零后进入可恢复的待回收状态；
- 上传完成前只写临时文件，服务端复算摘要成功后原子转正；
- 迁移旧路径时保存旧路径映射，重复迁移幂等，不覆盖同名不同内容。

## 5. 验收标准

1. 同一内容不同名称只产生一个物理对象；不同用户/目录产生各自逻辑条目。
2. 同一用户、同一父目录、同一展示名和同一对象的重复请求幂等；同名不同内容按服务端规则生成 `(1)` 等展示名。
3. 删除一个引用不影响其他引用读取；引用归零后才允许回收，异常中断可恢复。
4. 客户端伪造摘要、大小或物理路径不能访问其他对象，服务端复算不一致时不转正。
5. 现有用户路径、上传、下载、分享回归通过，迁移失败不会删除旧文件。

## 6. 不包含与停止条件

本分支不新增秒传 PDU、不改变现有分块协议、不实现乱序并发上传。若旧路径与新资产无法建立可审计的双向映射，停止进入秒传和群文件分支。
