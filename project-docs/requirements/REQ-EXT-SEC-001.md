# REQ-EXT-SEC-001 服务端身份与授权上下文

## 1. 分支信息

- 分支：`codex/req-ext-sec-001-auth-context`（身份授权上下文）
- 层级：LARGE 前置门；不单独提供用户可见业务功能
- 依赖：现有登录、注销和路径穿越防护基线
- 被依赖：所有群组和秒传/群文件分支

## 2. 目标

服务端为每个已登录连接建立不可由客户端覆盖的 `actor_context`（操作主体上下文），后续群角色、文件所有者、上传者和删除者都从该上下文得到。客户端提交的用户名、群主、上传者和物理路径只作为请求数据，不能作为授权依据。

## 3. 范围

### 必须实现

- 登录成功后绑定连接级用户标识和会话状态；未登录连接拒绝业务请求；
- 所有新增群/文件处理入口统一调用身份和资源权限校验；
- 断开、注销和会话失效时撤销业务访问；
- 文件路径统一解析为服务端生成的规范相对路径，保留现有路径穿越防护；
- 记录拒绝原因和请求关联标识，但不记录密码、完整令牌或文件敏感内容。

### 不包含

- TLS（传输层安全）、密码算法升级、Redis（缓存/限流服务）和多设备会话 UI；
- 群角色本身和文件资产表。

## 4. 验收标准

1. 未登录连接不能创建群、发送群消息、查询群成员、初始化上传或命中秒传。
2. 修改客户端 PDU 中的用户字段、上传者字段或路径字段不能获得其他用户资源。
3. 注销/断开后，旧连接再次发送业务请求被拒绝；旧连接不能继续访问群文件。
4. 正常一对一聊天、现有文件上传下载和路径防护回归通过。
5. 负向测试、日志片段、数据库状态和流水线报告均绑定候选提交哈希。

## 5. 风险与停止条件

- 若现有登录协议无法安全区分连接身份，停止后续群/文件开发，先补充会话版本或等价连接绑定。
- 若权限入口仍分散在 `MsgHandler`（消息处理器）各 case，审计不得接受“客户端隐藏按钮”作为权限证据。
- 不得在本分支顺手修改业务协议编号；需要新增字段时转入对应 LARGE 分支。
