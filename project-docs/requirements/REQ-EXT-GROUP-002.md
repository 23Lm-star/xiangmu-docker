# REQ-EXT-GROUP-002 可靠群文本消息

## 1. 分支信息

- 分支：`codex/req-ext-group-002-group-messaging`（群文本消息）
- 层级：LARGE；触碰消息协议、数据库并发和在线广播
- 依赖：`REQ-EXT-SEC-001`、`REQ-EXT-GROUP-001`

## 2. 目标

在已验证的群成员关系上提供文本群聊、在线广播、离线补偿、历史分页和未读数量。消息必须先持久化，再广播；网络重试不能产生重复消息。

## 3. 数据模型与并发

- `group_message`（群消息）：消息唯一标识、群标识、群内序号、服务端推导的发送者、文本内容、消息类型、创建时间。
- `(group_id, seq)` 唯一；群序号在事务中原子分配，不能依赖应用层读取后加一。
- 消息唯一标识用于客户端重试幂等；重复提交返回原消息确认，不重复广播。
- 单设备 MVP 可使用成员 `last_read_seq`（最后阅读序号）；若支持多设备，必须增加设备维度，禁止互相覆盖。

## 4. 处理流程

1. 服务端校验会话、群成员状态、禁言/发送频率和内容长度；忽略客户端 sender 字段。
2. 在事务中分配序号并写入消息，提交后向发送者返回“已持久化”确认。
3. 在线成员通过有界异步队列接收广播；慢连接不阻塞数据库事务或其他成员。
4. 登录/打开群聊时按序号或时间分页拉取缺失消息；阅读确认只推进当前成员允许推进的游标。
5. 成员加入、退出和移除作为系统消息或成员事件发送，事件顺序与群内序号规则一致。

## 5. 验收标准

1. 在线群成员可收到一次且仅一次的同一消息；发送方可区分服务端持久化成功和在线送达。
2. 离线成员重新登录后能按游标补齐消息，未读数量等于未读序号范围内的有效消息数。
3. 两个发送者并发发消息时，群内序号不重复、不倒退；数据库重试不重复写入。
4. 非成员、已退出成员和被移除成员不能发送、拉取或确认已读；历史消息权限即时失效。
5. 广播队列满、连接断开和数据库失败时有明确失败状态，不丢失已提交消息。
6. 一对一聊天、离线消息和现有文件功能回归通过。

## 6. 不包含与停止条件

本分支不实现富媒体、编辑/撤回/引用/转发、多设备完整投递状态和群文件。若无法证明“先提交后广播”或序号分配缺乏数据库锁定证据，独立测试只能报告 `BLOCKED`（阻塞）。
