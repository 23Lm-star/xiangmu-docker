# BUG-FILE-003 移动文件重名冲突 — 逻辑审查报告

## 1. 审查对象
- **代码文件**：`Server/msghandler.cpp`
- **目标函数**：`MsgHandler::movefile(const QString& loginName)`
- **修复版本**：R2 二次深度修复 + R3 静态审查修复

## 2. 逻辑路径追踪 (Trace)

### 2.1 路径构造与合法性校验
1. **源路径 (`srcPath`)**：由 `pdu->caMsg` (srcDir) 和 `pdu->caData` (fileName) 拼接。
2. **用户根目录 (`userRoot`)**：由配置的 `filesPath` 和 `loginName` 拼接。
3. **目标路径 (`dstPath`)**：固定为 `userRoot` + `fileName`。
   - **验证**：符合需求，即将文件移动到用户个人根目录下。
4. **校验逻辑**：
   - `canonicalSrc` 必须在 `userRoot` 前缀内（防止越界读取）。
   - `canonicalDstDir`（目标父目录）必须在 `userRoot` 前缀内（防止越界写入）。
   - **验证**：修复了 BUG-REV-FILE-005 中目标父目录不存在导致 `canonicalPath()` 为空的拦截问题（通过取父目录校验）。

### 2.2 自动重命名逻辑 (BUG-FILE-003 核心)
1. **冲突检测**：`if (QFileInfo::exists(finalDstPath))`。
2. **后缀提取**：正确处理了 `completeBaseName()` 和 `suffix()`，且 `suffix` 自动补点。
3. **递归探测**：
   - `do { ... } while (QFileInfo::exists(finalDstPath))`。
   - 生成格式：`baseName(count).suffix`。
   - **验证**：逻辑严密，`count` 自增且设有 `MAX_RETRIES` 防止死循环。
   - **修复确认**：解决了原版本中 `(1)(2)` 追加失败的问题。

### 2.3 降级策略 (BUG-REV-FILE-001/002)
1. **首选 `rename`**：直接调用 `QFile::rename(finalDstPath)`。
2. **降级 `copy + remove`**：
   - 若 `rename` 失败（跨文件系统典型场景），尝试 `QFile::copy`。
   - `copy` 成功后调用 `QFile::remove(srcPath)`。
   - **原子性保护**：若 `remove` 失败，会自动清理 `finalDstPath` 并返回 `false`。
   - **验证**：符合 R2 修复规格，解决了跨盘移动失败的问题。
