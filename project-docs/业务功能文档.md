# QT 云盘聊天系统业务功能文档

## 1. 文档说明

本文档以业务功能为中心，说明 QT 云盘聊天系统从用户操作开始，到客户端、TCP 协议、服务端、数据库和文件系统完成处理的完整过程。

当前已纳入：

1. 用户注册；
2. 用户登录。

本文档描述当前源码已经实现的行为。规划中的功能、改进建议和已知风险单独列出，不作为当前已完成流程。

### 1.1 系统参与模块

| 模块 | 主要职责 |
|---|---|
| Client | 登录/注册界面、TCP 连接、PDU 发送和接收 |
| Client::MsgHandler | 根据响应消息类型分发客户端处理逻辑 |
| Server::MyTcpServer | 监听 TCP 端口、接收客户端连接 |
| Server::MyTcpSocket | 管理单个客户端连接、拆包、请求分发、连接身份 |
| Server::MsgHandler | 注册、登录、验证码等业务处理 |
| OperateDB | 用户信息、在线状态等数据库操作 |
| DatabaseConnectionPool | 为数据库操作提供 RAII 连接 |
| 文件系统 | 保存用户云盘根目录 |

### 1.2 关键配置

客户端配置文件：Client/connect.config

服务端配置文件：Server/connect.config

配置结构：

~~~text
服务端 IP
服务端端口
文件根路径
数据库主机
数据库端口
数据库名称
数据库用户名
数据库密码
~~~

服务端用户目录：

~~~text
{Server.filesPath}/{用户名}/
~~~

当前默认文件根路径为 ./filesys，用户目录通常为：

~~~text
./filesys/{用户名}/
~~~

## 2. 通用通信流程

注册和登录都使用客户端与服务端之间的自定义 PDU 协议。

### 2.1 PDU 结构

~~~text
PDU
├── uiTotalLen       报文总长度
├── uiMsgLen         caMsg 消息体长度
├── uiType           请求或响应类型
├── caData[64]       固定参数区
└── caMsg[]          可变消息区
~~~

PDU 定义位置：

- Client/protocol.h
- Server/protocol.h

客户端使用 malloc/free 管理 PDU，服务端使用 memalloc/memfree 管理 PDU。两端不跨进程转移 PDU 所有权。

### 2.2 客户端发送流程

1. Qt 界面槽函数读取用户输入；
2. 客户端完成基础格式校验；
3. 客户端调用 mkPDU() 创建 PDU；
4. 设置 uiType；
5. 按协议将参数写入 caData 或 caMsg；
6. 调用 Client::seedMsg() 写入 TCP socket；
7. 写入后释放客户端 PDU。

### 2.3 服务端接收流程

1. readyRead 触发 MyTcpSocket::recvmsg()；
2. 读取 socket 数据并追加到连接级接收缓存 m_dpulist；
3. 根据 uiTotalLen 判断完整 PDU 是否已经到达；
4. 校验 PDU 总长度、消息体长度和消息类型；
5. 支持 TCP 半包和粘包；
6. 调用 MyTcpSocket::handlMsg()；
7. 根据 uiType 分发到 Server::MsgHandler；
8. 发送响应并释放服务端 PDU。

服务端限制：

- 单个入站 PDU 最大 16 KB；
- 待处理接收缓存最大 256 KB；
- 非法 PDU 达到阈值后断开连接。

## 3. 业务功能一：用户注册

### 3.1 业务目标

用户输入用户名、密码和验证码后，系统验证注册条件，创建用户数据库记录和用户云盘目录，并返回注册结果。

注册成功不代表用户已经登录，用户仍需使用账号和密码执行登录流程。

### 3.2 功能入口

客户端入口：

~~~cpp
Client::on_register_PB_clicked()
~~~

主要文件：Client/client.cpp

请求类型：

~~~cpp
ENUM_MSG_TYPE_REGIST_REQUEST = 1
~~~

响应类型：

~~~cpp
ENUM_MSG_TYPE_REGIST_RESPOND = 2
~~~

### 3.3 注册前置条件

客户端当前检查：

1. 验证码未处于锁定状态；
2. 用户名非空；
3. 密码非空；
4. 用户名 UTF-8 字节长度不超过 31；
5. 已经输入验证码。

服务端还会强制执行验证码校验，客户端校验不能替代服务端校验。

### 3.4 获取验证码

用户点击获取验证码后：

1. 客户端判断是否处于正常冷却期；
2. 客户端判断是否处于锁定期；
3. 客户端判断 TCP 是否连接；
4. 创建空消息体 PDU；
5. 设置 uiType = ENUM_MSG_TYPE_CAPTCHA_REQUEST；
6. 发送验证码请求。

服务端收到请求后：

1. 检查当前连接是否处于锁定期；
2. 检查当前连接是否处于获取冷却期；
3. 生成 6 位随机验证码；
4. 保存到当前连接的 MsgHandler；
5. 设置验证码有效期为 60 秒；
6. 设置重新获取冷却时间为 60 秒；
7. 返回验证码、状态码和剩余时间。

当前验证码规则：

| 参数 | 当前值 |
|---|---:|
| 验证码长度 | 6 位 |
| 验证码有效期 | 60 秒 |
| 正常重新获取冷却期 | 60 秒 |
| 连续错误上限 | 5 次 |
| 锁定时间 | 600 秒 |
| 验证码保存范围 | 当前 TCP 连接 |

客户端收到成功响应后，将验证码显示到输入框占位提示，并启动倒计时。

相关实现：

- 客户端请求：Client/client.cpp::on_pushButton_clicked()
- 服务端生成：Server/msghandler.cpp::captcha()
- 客户端处理：Client/msghandler.cpp::handleCaptcha()

### 3.5 注册请求 PDU

注册请求使用 ENUM_MSG_TYPE_REGIST_REQUEST，字段布局如下：

~~~text
uiType = 1
caData[0..31]   用户名，固定 32 字节字段
caData[32..63]  MD5 密码，固定 32 字节字段
caMsg[]         用户输入的验证码
uiMsgLen        验证码字节长度
~~~

密码处理：

~~~text
原始密码
  -> UTF-8 编码
  -> MD5
  -> 转为十六进制字符串
  -> 写入 caData[32..63]
~~~

### 3.6 客户端构造注册请求

点击注册后：

1. 判断验证码锁定状态；
2. 读取用户名和密码；
3. 检查用户名和密码是否为空；
4. 检查用户名长度；
5. 读取验证码输入内容；
6. 调用 mkPDU(captchaBytes.size() + 1)；
7. 设置消息类型为注册请求；
8. 计算密码 MD5；
9. 将用户名复制到 caData[0..31]；
10. 将 MD5 密码复制到 caData[32..63]；
11. 将验证码复制到 caMsg；
12. 发送 PDU。

### 3.7 服务端拆包和请求分发

服务端 MyTcpSocket::recvmsg()：

1. 读取 TCP 数据；
2. 追加到 m_dpulist；
3. 校验报文头；
4. 处理半包和粘包；
5. 校验 uiTotalLen、uiMsgLen 和 uiType；
6. 调用 handlMsg()。

当 uiType 为 ENUM_MSG_TYPE_REGIST_REQUEST 时，调用：

~~~cpp
m_MsgHandler->rigist()
~~~

### 3.8 服务端验证码校验

服务端在数据库操作前调用 validateCaptcha()。

校验顺序：

1. 如果连接处于锁定期，直接返回锁定状态；
2. 检查消息体长度；
3. 检查验证码是否存在；
4. 检查验证码是否过期；
5. 比较用户输入和当前连接保存的验证码；
6. 验证成功后清除验证码；
7. 验证成功后清零连续失败次数。

验证码结果：

| 返回值 | 含义 |
|---:|---|
| 0 | 验证成功 |
| -2 | 验证码错误或消息格式异常 |
| -3 | 验证码不存在或已过期 |
| -4 | 连续错误达到上限，锁定中 |

### 3.9 提取注册参数

验证码通过后，服务端从 PDU 提取：

~~~text
caData[0..31]   用户名
caData[32..63]  MD5 密码
~~~

固定字段读取时遇到 \\0 截断，再转换为 QString。

### 3.10 数据库注册操作

服务端调用：

~~~cpp
OperateDB::instance().handleRegit(name, password)
~~~

数据库操作如下。

#### 3.10.1 获取连接

从 DatabaseConnectionPool 获取 RAII 数据库连接。连接无效时注册失败。

#### 3.10.2 查询用户名

~~~sql
SELECT *
FROM user_info
WHERE name = ?
~~~

如果查询到记录，说明用户名已经存在，注册失败。

#### 3.10.3 插入用户

用户名不存在时执行：

~~~sql
INSERT INTO user_info(name, pwd)
VALUES (?, ?)
~~~

参数使用预处理绑定，不直接拼接用户输入。

注册记录：

| 字段 | 内容 |
|---|---|
| name | 用户名 |
| pwd | 客户端计算的 MD5 十六进制值 |
| online | 使用数据库默认值，注册后通常为 0 |

主要实现：Server/operatedb.cpp::handleRegit()

### 3.11 创建服务端用户目录

数据库插入成功后，服务端创建：

~~~text
{filesPath}/{用户名}/
~~~

当前实现还会尝试创建文件根目录：

~~~text
{filesPath}/
~~~

注册成功后的服务端文件状态：

~~~text
filesys/
└── 用户名/
~~~

### 3.12 注册响应 PDU

服务端返回 ENUM_MSG_TYPE_REGIST_RESPOND：

~~~text
caData[0..3]    注册结果
caData[32..63]  用户名
~~~

结果值：

| 值 | 含义 |
|---:|---|
| 非零成功值 | 注册成功 |
| 0 | 数据库注册失败或用户名已存在 |
| -2 | 验证码错误 |
| -3 | 验证码过期 |
| -4 | 验证码锁定 |

### 3.13 客户端处理注册结果

客户端收到响应后调用 MsgHandler::handlrigist()。

注册成功：

1. 显示加载动画；
2. 延迟 1.5 秒；
3. 弹出“注册成功”；
4. 清空用户名输入框；
5. 清空密码输入框；
6. 在客户端本地创建用户目录。

客户端本地目录：

~~~text
{Client.m_strRootPath}/{用户名}/
~~~

注册失败：

| 错误 | 提示或处理 |
|---|---|
| -2 | 验证码错误，请重新输入 |
| -3 | 验证码已过期，请重新获取 |
| -4 | 启动 10 分钟锁定倒计时并禁用注册/登录 |
| 0 | 关闭加载动画，保留当前输入 |

### 3.14 注册完整时序

~~~text
用户
 │
 ├── 输入用户名、密码、验证码
 ├── 获取验证码
 │     ├── Client 发送 CAPTCHA_REQUEST
 │     ├── Server 生成并保存验证码
 │     └── Client 显示验证码并启动冷却
 │
 └── 点击注册
       ├── Client 校验输入
       ├── Client 计算密码 MD5
       ├── Client 发送 REGIST_REQUEST
       ├── Server 拆包并校验 PDU
       ├── Server 校验验证码
       ├── Server 查询用户名
       ├── Server 插入 user_info
       ├── Server 创建用户目录
       ├── Server 返回 REGIST_RESPOND
       └── Client 显示注册结果并创建本地目录
~~~

### 3.15 注册数据变化

数据库：

~~~text
新增 user_info 记录
online = 0
~~~

服务端文件系统：

~~~text
新增 filesPath/{用户名}/
~~~

客户端文件系统：

~~~text
新增 m_strRootPath/{用户名}/
~~~

### 3.16 注册验证项

1. 正确用户名、密码和验证码注册成功；
2. 重复用户名注册失败；
3. 错误验证码注册失败；
4. 验证码过期后注册失败；
5. 连续 5 次验证码错误后锁定 10 分钟；
6. 60 秒冷却期内重复获取验证码被拒绝；
7. 数据库新增用户记录；
8. 服务端生成用户目录；
9. 客户端生成本地用户目录；
10. TCP 半包和粘包情况下注册请求仍能正常处理；
11. 数据库连接异常时不创建虚假的成功状态。

### 3.17 注册当前风险

1. 用户名格式主要由客户端检查，服务端没有完整强制校验，只检查字段并参与目录拼接；
2. 数据库先查询再插入，没有依靠唯一索引和事务保证并发注册的一致性；
3. 数据库插入成功、目录创建失败时，可能出现账号存在但用户目录不存在；
4. 密码使用无盐 MD5；
5. 验证码失败计数保存在当前连接，不是按账号或 IP 全局统计；
6. 注册失败时没有区分用户名重复、数据库异常等具体原因。

## 4. 业务功能二：用户登录

### 4.1 业务目标

用户输入用户名、密码和验证码后，系统验证认证信息，将用户设置为在线，并将当前 TCP 连接绑定到该用户，最后进入云盘聊天系统主界面。

登录成功后，用户可以继续使用好友、聊天、文件和分享等业务功能。

### 4.2 功能入口

客户端入口：

~~~cpp
Client::on_login_PB_clicked()
~~~

主要文件：Client/client.cpp

请求类型：

~~~cpp
ENUM_MSG_TYPE_LOGIN_REQUEST = 3
~~~

响应类型：

~~~cpp
ENUM_MSG_TYPE_LOGIN_RESPOND = 4
~~~

### 4.3 登录前置校验

客户端当前检查：

1. 验证码锁定状态；
2. 验证码非空；
3. 用户名非空；
4. 密码非空；
5. 用户名 UTF-8 字节长度不超过 31。

客户端不直接判断用户名是否存在，也不判断密码是否正确，这些认证必须由服务端完成。

### 4.4 登录请求 PDU

~~~text
uiType = 3
caData[0..31]   用户名，固定 32 字节字段
caData[32..63]  MD5 密码，固定 32 字节字段
caMsg[]         用户输入的验证码
uiMsgLen        验证码字节长度
~~~

密码处理流程与注册一致：

~~~text
原始密码
  -> UTF-8 编码
  -> MD5
  -> 十六进制字符串
  -> 写入 caData[32..63]
~~~

### 4.5 客户端构造登录请求

点击登录后：

1. 判断是否锁定；
2. 读取验证码；
3. 验证码为空时直接提示并结束；
4. 读取用户名和密码；
5. 校验用户名和密码；
6. 调用 mkPDU(captchaBytes.size() + 1)；
7. 设置 uiType = ENUM_MSG_TYPE_LOGIN_REQUEST；
8. 计算密码 MD5；
9. 写入用户名；
10. 写入 MD5 密码；
11. 写入验证码；
12. 调用 Client::seedMsg() 发送。

### 4.6 服务端拆包和请求分发

服务端接收登录请求时，统一经过 MyTcpSocket::recvmsg()：

1. 读取 socket 数据；
2. 写入连接接收缓存；
3. 判断完整 PDU；
4. 检查 PDU 长度和消息类型；
5. 处理半包和粘包；
6. 分发到 MyTcpSocket::handlMsg()。

登录请求分发到：

~~~cpp
m_MsgHandler->login(this->m_strLoginName)
~~~

这里传入当前连接的 m_strLoginName 引用，登录成功后由登录处理函数写入当前 socket。

### 4.7 服务端验证码校验

服务端先执行 validateCaptcha()，数据库验证之前不会查询用户名和密码。

校验流程：

1. 判断连接是否处于锁定期；
2. 判断验证码消息体长度；
3. 判断当前连接是否有有效验证码；
4. 判断验证码是否过期；
5. 比较用户输入和服务端验证码；
6. 成功后一次性作废当前验证码；
7. 成功后清零失败次数。

验证码失败时，服务端直接返回登录响应，不执行数据库认证。

### 4.8 提取用户名和密码

验证码通过后，服务端读取：

~~~text
caData[0..31]   用户名
caData[32..63]  MD5 密码
~~~

服务端将固定字段转换为 QString，得到 username 和 userpwd。

### 4.9 数据库认证

服务端调用：

~~~cpp
OperateDB::instance().handleLogin(username, userpwd)
~~~

数据库认证步骤：

1. 从数据库连接池获取连接；
2. 连接无效时返回 0；
3. 按用户名查询用户；
4. 按用户名和密码查询完整用户记录；
5. 查询不到匹配记录时返回 -1；
6. 查询成功时更新在线状态；
7. 在线状态更新成功后返回 1。

认证 SQL：

~~~sql
SELECT *
FROM user_info
WHERE name = ?
  AND pwd = ?
~~~

返回值：

| 返回值 | 含义 |
|---:|---|
| 1 | 用户名和密码正确，且在线状态更新成功 |
| -1 | 用户不存在或密码错误 |
| 0 | 数据库连接、查询或在线状态更新异常 |

数据库实现位置：Server/operatedb.cpp::handleLogin()

### 4.10 更新在线状态

认证成功后执行：

~~~sql
UPDATE user_info
SET online = 1
WHERE name = ?
  AND pwd = ?
~~~

数据变化：

~~~text
user_info.online: 0 -> 1
~~~

在线状态更新失败时，服务端返回 0，客户端不能进入成功流程。

### 4.11 绑定服务端连接身份

数据库认证返回 1 后：

~~~cpp
strname = username;
~~~

由于 strname 引用的是 MyTcpSocket::m_strLoginName，当前连接会保存：

~~~text
m_strLoginName = 当前用户名
~~~

后续业务根据该字段确定当前用户，例如查询好友、发送聊天、访问云盘、上传下载文件和处理分享链接。

### 4.12 登录响应 PDU

服务端返回 ENUM_MSG_TYPE_LOGIN_RESPOND：

~~~text
caData[0..3]    登录结果 ret
caData[32..63]  用户名
~~~

返回值：

| 值 | 含义 |
|---:|---|
| 1 | 登录成功 |
| -1 | 用户不存在或密码错误 |
| 0 | 服务端或数据库异常 |
| -2 | 验证码错误 |
| -3 | 验证码过期 |
| -4 | 验证码锁定 |

### 4.13 客户端处理登录响应

客户端根据响应类型调用 MsgHandler::handllogin()。

验证码错误或过期时，分别提示重新输入或重新获取。

验证码锁定时：

1. 读取服务端返回的剩余锁定秒数；
2. 启动客户端倒计时；
3. 禁用获取验证码、注册和登录按钮；
4. 提示用户等待锁定结束。

用户名或密码错误时：

1. 关闭加载动画；
2. 延迟 1.5 秒；
3. 提示“用户或密码其中一个错误”；
4. 保留登录界面。

服务端异常时：

1. 关闭加载动画；
2. 延迟 1.5 秒；
3. 提示“状态异常”。

### 4.14 登录成功后的客户端处理

当服务端返回 ret == 1 时：

1. 显示加载动画；
2. 从响应 caData + 32 读取用户名；
3. 延迟 1.5 秒；
4. 写入 Client::m_LoginName；
5. 显示 Index 主界面；
6. 隐藏登录窗口；
7. 在下一个事件循环中刷新好友列表。

客户端状态变化：

~~~text
Client::m_LoginName = 当前用户名
Index 主界面 = 显示
Client 登录窗口 = 隐藏
~~~

### 4.15 登录后的初始数据加载

登录成功后自动执行：

~~~cpp
Index::getinstance().getFriend()->flushfriend();
~~~

当前加载策略：

| 数据 | 加载时机 |
|---|---|
| 好友列表 | 登录成功后自动刷新 |
| 文件列表 | 用户首次进入文件页面时刷新 |
| 在线用户列表 | 用户打开在线用户页面时获取 |
| 聊天记录 | 进入聊天或好友聊天流程时获取 |

### 4.16 登录完整时序

~~~text
用户
 │
 ├── 输入用户名和密码
 ├── 获取验证码
 │     ├── Client 发送 CAPTCHA_REQUEST
 │     ├── Server 生成验证码并保存到当前连接
 │     └── Client 显示验证码并启动冷却
 │
 └── 点击登录
       ├── Client 检查输入
       ├── Client 对密码执行 MD5
       ├── Client 发送 LOGIN_REQUEST
       ├── Server 拆包并校验 PDU
       ├── Server 校验验证码
       ├── Server 查询用户名和密码
       ├── Server 更新 user_info.online = 1
       ├── Server 保存 MyTcpSocket.m_strLoginName
       ├── Server 返回 LOGIN_RESPOND
       ├── Client 解析结果
       ├── Client 保存 m_LoginName
       ├── Client 显示 Index 主界面
       ├── Client 隐藏登录界面
       └── Client 自动刷新好友列表
~~~

### 4.17 断开连接后的下线处理

当前 TCP 连接断开时触发 MyTcpSocket::clientOffLine()：

1. 关闭并释放下载文件；
2. 清理下载状态；
3. 调用 OperateDB::handleOffLine(m_strLoginName)；
4. 执行在线状态更新；
5. 从服务端连接列表移除当前 socket。

执行 SQL：

~~~sql
UPDATE user_info
SET online = 0
WHERE name = ?
~~~

### 4.18 登录与心跳关系

客户端创建 30 秒心跳定时器，周期性发送 ENUM_MSG_TYPE_HEARTBEAT_REQUEST，服务端返回 ENUM_MSG_TYPE_HEARTBEAT_RESPOND。

如果服务端长时间没有响应：

1. 客户端判断连接失效；
2. 显示重连界面；
3. 尝试恢复 TCP 连接；
4. 连接恢复后回到登录界面；
5. 要求用户重新登录。

重新登录是必要的，因为服务端重启或创建新连接后，原来的 m_strLoginName 不会自动恢复。

### 4.19 登录验证项

1. 正确用户名、密码和验证码登录成功；
2. 用户不存在时登录失败；
3. 密码错误时登录失败；
4. 验证码错误时登录失败；
5. 验证码过期时登录失败；
6. 连续验证码错误 5 次后进入锁定；
7. 登录成功后 user_info.online 为 1；
8. 登录成功后服务端连接保存正确用户名；
9. 登录成功后显示主界面；
10. 登录成功后自动刷新好友列表；
11. 登录成功后文件模块使用正确用户目录；
12. 断开连接后 user_info.online 恢复为 0；
13. TCP 半包和粘包情况下登录请求仍能正常处理；
14. 数据库连接池不可用时客户端得到失败结果；
15. 服务端重启后客户端不会沿用旧登录身份。

### 4.20 登录当前风险

1. Client::handlMsg() 当前在收到任意登录响应后都执行 m_loggedIn = true，失败响应也可能被标记为已登录；
2. 同一个账号可以建立多个连接，某个连接断开时可能把其他仍在线连接对应的用户状态错误改为离线；
3. 未登录连接断开时仍可能执行用户名为空的下线 SQL；
4. 后续业务依赖 m_strLoginName 作为身份状态，需要统一增加服务端已登录校验；
5. 密码使用无盐 MD5，存在离线破解风险；
6. 服务端日志当前可能输出密码哈希或认证诊断信息，生产环境应关闭；
7. 用户名格式主要由客户端校验，服务端仍需再次校验；
8. 登录认证和在线状态更新没有封装为完整事务；
9. 账号没有独立的会话、过期和主动注销状态管理。

## 5. 业务功能三：好友管理

### 5.1 业务范围

好友管理包括：

1. 查找用户；
2. 获取可添加的在线用户；
3. 发送好友申请；
4. 同意好友申请；
5. 拒绝好友申请；
6. 刷新好友列表；
7. 删除好友；
8. 从好友列表进入一对一聊天。

当前好友申请只在在线 TCP 连接之间转发，好友关系通过 friend 表保存。

### 5.2 好友关系数据模型

当前源码使用以下字段保存好友关系：

~~~text
friend.name
friend.friendName
~~~

建立关系时插入一条记录，例如：

~~~text
name = user_a
friendName = user_b
~~~

查询好友时同时查询两个方向：

~~~sql
SELECT friendName
FROM friend
WHERE name = ?

UNION

SELECT name
FROM friend
WHERE friendName = ?
~~~

因此双方都可以查询到对方。删除好友时，同时删除两个方向的记录。

### 5.3 查找用户

#### 客户端流程

用户点击查找用户后：

1. 弹出用户名输入框；
2. 读取目标用户名；
3. 创建 PDU；
4. 设置消息类型为 ENUM_MSG_TYPE_findUser_REQUEST；
5. 将目标用户名写入 caData[0..31]；
6. 发送请求。

请求结构：

~~~text
uiType = 5
caData[0..31] = 被查找用户名
caMsg[]        空
~~~

#### 服务端流程

服务端读取目标用户名，调用 OperateDB::handleFindUser。

数据库查询：

~~~sql
SELECT *
FROM user_info
WHERE name = ?
~~~

返回值：

| 返回值 | 含义 |
|---:|---|
| 1 | 用户存在且在线 |
| 0 | 用户存在但不在线 |
| 2 | 用户不存在 |
| -1 | 参数或数据库连接异常 |

服务端返回 ENUM_MSG_TYPE_findUser_RESPOND，并将结果写入 caData[0..3]。客户端分别提示用户不存在、用户在线或用户不在线。

### 5.4 获取可添加的在线用户

用户点击在线用户后：

1. 客户端显示在线用户窗口；
2. 创建 ENUM_MSG_TYPE_ONLINEUSER_REQUEST；
3. 发送到服务端；
4. 服务端使用当前连接的 m_strLoginName 作为当前用户；
5. 查询在线且不是好友的用户；
6. 返回用户名列表；
7. 客户端刷新在线用户窗口。

服务端查询条件：

~~~sql
SELECT name
FROM user_info
WHERE online = 1
  AND name != ?
  AND name NOT IN (
      SELECT friendName FROM friend WHERE name = ?
      UNION
      SELECT name FROM friend WHERE friendName = ?
  )
~~~

结果排除当前用户自己、已有好友和不在线用户。

响应类型为 ENUM_MSG_TYPE_ONLINEUSER_RESPOND。每个用户名占用 caMsg 中的 32 字节，客户端读取后增加显示序号，例如：

~~~text
1.user_a
2.user_b
~~~

### 5.5 发送好友申请

用户双击在线用户列表项后：

1. 去掉显示序号；
2. 提取目标用户名；
3. 获取当前登录用户名；
4. 创建 ENUM_MSG_TYPE_ADDFRIEND_REQUEST；
5. 写入申请人和目标用户；
6. 发送到服务端。

请求结构：

~~~text
caData[0..31]   当前用户
caData[32..63]  目标用户
~~~

服务端收到请求后：

1. 提取申请人和目标用户；
2. 查询目标用户是否在线；
3. 目标用户不在线时直接返回失败；
4. 目标用户在线时创建转发 PDU；
5. 根据目标用户名查找目标 socket；
6. 将申请转发给目标用户。

在线检查：

~~~sql
SELECT *
FROM user_info
WHERE name = ?
  AND online = 1
~~~

### 5.6 处理好友申请

目标用户收到申请后，客户端弹出确认框：

~~~text
你同意 user_a 的好友申请吗?
~~~

用户点击同意后：

1. 获取当前登录用户名；
2. 获取申请发起人；
3. 创建 ENUM_MSG_TYPE_ADDFRIEND_RESPOND；
4. 将同意人写入 caData[0..31]；
5. 将申请发起人写入 caData[32..63]；
6. 发送到服务端。

用户点击拒绝后，当前客户端直接结束处理，不发送拒绝响应，数据库不发生变化。

### 5.7 建立好友关系

服务端收到同意响应后：

1. 读取同意人和申请发起人；
2. 调用 handleAddFriendFin；
3. 开启数据库事务；
4. 插入好友关系；
5. 插入失败时回滚；
6. 插入成功后提交；
7. 创建好友建立结果响应；
8. 分别通知申请发起人和同意人；
9. 双方客户端收到成功结果后刷新好友列表。

插入 SQL：

~~~sql
INSERT INTO friend(name, friendName)
VALUES (?, ?)
~~~

当前实际插入一条方向记录，双方查询时通过正向和反向 UNION 获取对方。

### 5.8 刷新好友列表

刷新触发场景：

1. 登录成功后；
2. 用户点击刷新；
3. 好友建立成功后；
4. 删除好友成功后。

客户端发送空参数的 ENUM_MSG_TYPE_FLUSHFRIEND_REQUEST。服务端使用当前 socket 的 m_strLoginName 查询好友。

响应类型为 ENUM_MSG_TYPE_FLUSHFRIEND_RESPOND，每个好友占用 32 字节。

客户端收到后：

1. 读取好友用户名；
2. 增加显示序号；
3. 缓存到 m_friendList；
4. 页面可见时排队刷新列表；
5. 页面不可见时延迟到页面显示后刷新；
6. 清理旧列表并显示新列表。

### 5.9 删除好友

客户端删除流程：

1. 选择好友列表项；
2. 去除前面的序号；
3. 弹出删除确认；
4. 获取目标好友和当前用户名；
5. 创建 ENUM_MSG_TYPE_DELETEFRIEND_REQUEST；
6. 将目标好友和当前用户写入 PDU；
7. 发送请求。

请求字段：

~~~text
caData[0..31]   目标好友
caData[32..63]  当前用户
~~~

服务端使用事务删除双方关系：

~~~sql
DELETE FROM friend
WHERE (name = ? AND friendName = ?)
   OR (name = ? AND friendName = ?)
~~~

删除成功后，服务端还会删除双方聊天记录：

~~~sql
DELETE FROM message_info
WHERE (seed_name = ? AND rev_name = ?)
   OR (seed_name = ? AND rev_name = ?)
~~~

服务端返回 ENUM_MSG_TYPE_DELETEFRIEND_RESPOND，客户端成功后重新刷新好友列表。

### 5.10 从好友列表进入聊天

用户选择好友并点击聊天后：

1. 提取好友真实用户名；
2. 保存到 m_strChatName；
3. 显示聊天窗口；
4. 设置窗口标题；
5. 构造 ENUM_MSG_TYPE_GETCHATMSG_REQUEST；
6. 将当前用户和聊天对象写入 caData；
7. 请求该好友发送给当前用户的未读消息。

好友管理负责选择聊天对象，消息发送和消息存储由即时聊天功能负责。

### 5.11 好友管理时序

~~~text
当前用户
 │
 ├── 查看在线用户
 │     ├── Client 发送 ONLINEUSER_REQUEST
 │     ├── Server 查询在线且非好友用户
 │     └── Client 显示列表
 │
 ├── 双击目标用户
 │     ├── Client 发送 ADDFRIEND_REQUEST
 │     ├── Server 检查目标是否在线
 │     ├── Server 转发申请
 │     └── 目标用户显示确认框
 │
 ├── 目标用户同意
 │     ├── Target Client 发送 ADDFRIEND_RESPOND
 │     ├── Server 开启事务
 │     ├── Server 写入 friend
 │     ├── Server 提交事务
 │     ├── Server 通知双方
 │     └── 双方刷新好友列表
 │
 └── 目标用户拒绝
       ├── Client 不发送响应
       ├── Server 不写数据库
       └── 申请人不会收到明确拒绝通知
~~~

### 5.12 好友管理业务风险

1. 好友申请中的申请人用户名来自客户端 PDU，服务端没有强制替换为当前连接身份；
2. 服务端没有完整校验双方是否已经是好友，可能重复建立关系；
3. 服务端目标用户离线时返回值和客户端“不在线”提示判断不一致；
4. 同意申请时客户端没有统一释放发送 PDU，可能造成申请确认后的异常行为；
5. 用户拒绝申请时没有返回结果，申请人无法知道申请已被拒绝；
6. 好友申请不持久化，目标用户离线或服务端重启后申请会消失；
7. 删除好友会同时删除聊天记录，可能造成用户认为的历史数据丢失；
8. 删除操作不会实时通知另一方，另一方需要刷新好友列表；
9. 在线状态是账号级状态，同一账号多连接时可能出现好友列表状态不一致；
10. 列表项通过“序号.用户名”解析，用户名包含点号时可能影响好友选择。

### 5.13 好友管理业务扩展

1. 增加好友申请表，支持离线申请、申请状态和申请时间；
2. 增加同意、拒绝、忽略和撤回申请；
3. 增加好友申请通知和未处理数量；
4. 增加好友备注、分组和标签；
5. 增加黑名单、拉黑和解除拉黑；
6. 增加删除好友前是否保留聊天记录的选择；
7. 增加好友状态实时推送；
8. 增加好友在线、离线和最后在线时间；
9. 增加好友搜索、排序和批量管理；
10. 增加好友资料页和好友权限设置；
11. 增加好友推荐和共同好友；
12. 增加群聊入口和群成员管理。

### 5.14 好友管理验证项

1. 查找存在、在线、离线和不存在用户；
2. 在线用户列表排除自己和已有好友；
3. 在线目标用户可以收到好友申请；
4. 离线目标用户得到明确业务提示；
5. 目标用户同意后双方都能看到好友；
6. 目标用户拒绝后没有新增关系；
7. 登录后好友列表自动刷新；
8. 删除好友后双方关系都消失；
9. 删除好友后的聊天记录符合产品规则；
10. 好友列表快速刷新时不会显示错误数据；
11. 好友名称特殊字符不会破坏列表选择；
12. 多个客户端同时处理好友申请时关系数据正确。

## 6. 业务功能四：一对一即时聊天

### 6.1 业务目标

用户从好友列表选择好友后，可以发送即时消息。好友在线时消息实时转发，好友离线时消息保存到数据库，好友上线后进入对应聊天窗口即可拉取未读消息。

当前聊天仅支持一对一消息，不支持群聊。

### 6.2 进入聊天窗口

客户端从好友列表获取目标好友后：

1. 去除好友列表项前的序号；
2. 保存真实用户名到 m_strChatName；
3. 显示聊天窗口；
4. 设置窗口标题；
5. 发送获取聊天消息请求。

请求类型：

~~~cpp
ENUM_MSG_TYPE_GETCHATMSG_REQUEST
~~~

请求字段：

~~~text
caData[0..31]   当前登录用户
caData[32..63]  聊天对象
~~~

### 6.3 发送聊天消息

用户点击发送后：

1. 读取输入框内容；
2. 获取当前时间；
3. 空消息不发送；
4. 清空输入框；
5. 计算消息 PDU 总长度；
6. 设置聊天请求类型；
7. 写入发送人和接收人；
8. 构造 Msg；
9. 写入消息正文和发送时间；
10. 发送到服务端。

聊天请求类型为 ENUM_MSG_TYPE_CHAT_REQUEST。

### 6.4 聊天请求 PDU

~~~text
PDU
├── uiType = ENUM_MSG_TYPE_CHAT_REQUEST
├── caData[0..31]   发送人
├── caData[32..63]  接收人
└── caMsg[]
    └── Msg
        ├── totalLen
        ├── msgLen
        ├── Time[30]
        └── msg[]
~~~

Msg 的 totalLen 用于在多个连续消息之间移动，msgLen 表示正文长度。

### 6.5 服务端处理在线消息

服务端收到聊天请求后：

1. 读取发送人；
2. 读取接收人；
3. 读取消息正文；
4. 读取发送时间；
5. 查询接收人是否在线；
6. 将消息写入 message_info；
7. 在线时将 issuccess 写为 1；
8. 调用 MyTcpServer::reseed 转发原始 PDU。

在线检查：

~~~sql
SELECT *
FROM user_info
WHERE name = ?
  AND online = 1
~~~

消息保存：

~~~sql
INSERT INTO message_info(seed_name, rev_name, msg, issuccess, seed_time)
VALUES (?, ?, ?, ?, ?)
~~~

服务端不会为聊天请求返回独立响应，处理函数返回空 PDU。

### 6.6 在线消息转发和显示

服务端根据接收人用户名查找目标 socket，并把聊天 PDU 转发给目标客户端。

目标客户端收到 ENUM_MSG_TYPE_CHAT_REQUEST 后：

1. 读取发送人；
2. 读取消息正文；
3. 读取发送时间；
4. 拼接显示文本；
5. 写入聊天显示框；
6. 聊天窗口隐藏时显示窗口；
7. 将窗口标题设置为发送人。

显示格式：

~~~text
user_a:你好 发送时间:...
~~~

### 6.7 服务端保存离线消息

如果接收人不在线，服务端仍然写入 message_info，但设置：

~~~text
issuccess = 0
~~~

此时不进行实时转发。

### 6.8 上线后获取离线消息

接收方登录后进入聊天窗口，客户端发送 ENUM_MSG_TYPE_GETCHATMSG_REQUEST。

服务端将请求解析为：

~~~text
seedName = 聊天对象
revName = 当前登录用户
~~~

然后查询：

~~~sql
SELECT msg, seed_time
FROM message_info
WHERE seed_name = ?
  AND rev_name = ?
  AND issuccess = 0
~~~

查询结果被组装成多个连续的 Msg，放入 ENUM_MSG_TYPE_GETCHATMSG_RESPOND：

~~~text
caMsg
├── Msg 1
├── Msg 2
├── Msg 3
└── ...
~~~

客户端通过每条消息的 totalLen 读取下一条消息，直到达到 uiMsgLen。

### 6.9 标记离线消息

服务端查询离线消息后执行：

~~~sql
UPDATE message_info
SET issuccess = 1
WHERE seed_name = ?
  AND rev_name = ?
~~~

当前 issuccess 的业务含义：

~~~text
0 = 尚未被接收方拉取
1 = 已被认为送达或已处理
~~~

它还没有区分已发送、已送达和已读三个状态。

### 6.10 客户端展示离线消息

客户端收到聊天记录响应后：

1. 从 caMsg 读取一条 Msg；
2. 提取消息正文；
3. 提取发送时间；
4. 按 totalLen 移动到下一条；
5. 重复直到消息体结束；
6. 将消息列表交给聊天窗口；
7. 逐条展示。

### 6.11 当前聊天窗口行为

当前客户端在聊天窗口隐藏时才会设置聊天对象并请求聊天记录。

如果聊天窗口已经显示，再选择其他好友不会完整执行切换聊天对象、清理旧内容和重新请求历史消息的流程。

### 6.12 聊天时序

在线消息：

~~~text
发送方
 │
 ├── 输入消息并点击发送
 ├── Client 构造 CHAT_REQUEST
 ├── Server 提取消息参数
 ├── Server 查询接收人在线状态
 ├── Server 写入 message_info，issuccess = 1
 ├── Server 转发 CHAT_REQUEST
 └── 接收方 Client 显示消息
~~~

离线消息：

~~~text
发送方
 │
 ├── 发送 CHAT_REQUEST
 ├── Server 查询接收人离线
 ├── Server 写入 message_info，issuccess = 0
 └── 暂不转发

接收方上线
 │
 ├── 登录成功
 ├── 打开对应聊天窗口
 ├── 发送 GETCHATMSG_REQUEST
 ├── Server 查询 issuccess = 0 的消息
 ├── Server 返回 GETCHATMSG_RESPOND
 ├── Server 更新 issuccess = 1
 └── Client 展示消息
~~~

### 6.13 聊天业务风险

1. 发送人用户名来自客户端 PDU，服务端没有强制使用当前 TCP 连接身份；
2. 服务端没有完整检查发送双方是否为好友，可能向非好友用户发送消息；
3. 接收人数据库状态为在线时，消息会被标记为已处理，但实际 socket 转发失败时用户可能没有收到；
4. 发送方没有独立的发送成功、送达和失败反馈，也不会立即显示自己的消息；
5. 当前只拉取 issuccess = 0 的离线消息，不是完整聊天历史；
6. 查询后直接批量标记已处理，客户端展示前异常退出可能造成消息无法再次拉取；
7. 离线消息查询没有明确的时间排序，显示顺序可能不稳定；
8. 聊天窗口切换不完整，切换好友时可能继续显示或请求前一个好友的内容；
9. 删除好友会清理双方聊天记录；
10. 当前没有明确的聊天消息长度规则，超长消息无法提供稳定业务反馈；
11. 当前没有消息唯一编号，重复拉取或多端同步时不容易去重。

### 6.14 聊天业务扩展

1. 增加消息唯一 ID；
2. 增加发送中、已发送、已送达、已读状态；
3. 增加发送方消息回显；
4. 增加消息失败重试；
5. 增加未读消息数量和上线提醒；
6. 增加完整历史记录、分页和按时间加载；
7. 增加聊天内容搜索；
8. 增加图片、文件、语音、视频和表情消息；
9. 增加引用、转发、撤回、编辑和收藏；
10. 增加黑名单、免打扰和消息举报；
11. 增加群聊、群成员和群权限；
12. 增加多设备消息同步；
13. 增加聊天记录导出、备份和恢复；
14. 增加消息过期和历史记录保留策略。

### 6.15 聊天验证项

1. 好友在线时消息可以实时到达；
2. 好友离线时消息可以写入数据库；
3. 好友上线后可以拉取离线消息；
4. 离线消息内容和时间显示正确；
5. 多条离线消息能够按消息边界完整解析；
6. 空消息不会发送；

11. 大量离线消息不会造成聊天界面异常；
12. 多客户端登录时消息状态不会错误覆盖。

## 7. 业务功能五：云盘文件管理基础操作

### 7.1 业务范围

本章覆盖：

1. 刷新文件列表；
2. 进入子目录；
3. 返回上级目录；
4. 手动输入路径；
5. 创建文件夹；
6. 删除文件或目录；
7. 重命名文件或目录。

上传、断点续传、下载、好友文件分享和分享链接属于后续独立业务功能。

### 7.2 目录和文件状态

客户端维护：

~~~cpp
m_strUserPath  // 当前用户根目录
m_strCurPath   // 当前浏览目录
~~~

登录后：

~~~text
m_strUserPath = {客户端根目录}/{用户名}
m_strCurPath = m_strUserPath
~~~

服务端用户目录：

~~~text
{Server.filesPath}/{用户名}/
~~~

文件列表条目使用：

~~~text
FileInfo
├── caName[32]  文件或目录名称
└── uiType       0=目录，1=普通文件
~~~

### 7.3 刷新文件列表

触发场景：

1. 首次进入文件页面；
2. 点击刷新；
3. 进入子目录；
4. 返回上级目录；
5. 创建目录成功；
6. 删除成功；
7. 重命名成功；
8. 上传成功；
9. 接收分享文件成功。

客户端调用 File::flushfile()：

1. 读取 m_strCurPath；
2. 将路径转换为 UTF-8；
3. 创建 PDU；
4. 设置 ENUM_MSG_TYPE_FLUSHFILE_REQUEST；
5. 将当前路径写入 caMsg；
6. 发送请求。

请求结构：

~~~text
uiType = 23
caMsg[] = 当前目录路径
~~~

服务端调用 MsgHandler::flushfile()：

1. 读取目录路径；
2. 创建 QDir；
3. 获取目录条目；
4. 为每个条目创建 FileInfo；
5. 设置文件名；
6. 设置目录或普通文件类型；
7. 将条目写入响应消息体。

响应类型为 ENUM_MSG_TYPE_FLUSHFILE_RESPOND。客户端按 sizeof(FileInfo) 读取条目，保存到 m_fileInfoList，并使用不同图标显示目录和普通文件。

### 7.4 进入子目录

用户双击文件列表项后：

1. 根据缓存的 uiType 判断类型；
2. 如果是目录，将目录名追加到 m_strCurPath；
3. 更新当前路径输入框；
4. 发送 FLUSHFILE_REQUEST；
5. 显示子目录内容。

例如：

~~~text
原路径：./filesys/user_a
双击：documents
新路径：./filesys/user_a/documents
~~~

双击普通文件时，当前实现不执行打开、预览或下载操作。

### 7.5 返回上级目录

客户端点击返回后：

1. 判断当前路径是否等于用户根目录；
2. 如果已经是根目录，直接结束；
3. 找到当前路径最后一个斜杠；
4. 删除当前目录名称；
5. 更新路径输入框；
6. 发送刷新请求。

客户端不允许通过返回按钮进入用户根目录之外。

### 7.6 手动输入路径

用户输入路径后点击跳转：

1. 客户端读取目标路径；
2. 创建 ENUM_MSG_TYPE_CHANGEDIR_REQUEST；
3. 将路径写入 caMsg；
4. 发送到服务端。

服务端：

1. 判断路径是否存在；
2. 如果是目录，返回该目录；
3. 如果是文件，返回该文件的父目录；
4. 如果不存在，返回失败；
5. 将结果和路径写入响应。

成功响应后客户端更新 m_strCurPath 并刷新列表。失败响应后提示路径不存在，并恢复路径输入框。

### 7.7 创建文件夹

客户端创建前校验：

1. 名称非空；
2. 前后不能有空格；
3. 不能是点或点点；
4. UTF-8 字节长度不超过 31；
5. 不能以点号或空格结尾；
6. 不能包含 Windows 禁止字符；
7. 不能包含控制字符；
8. 不能使用 Windows 保留名称。

请求类型为 ENUM_MSG_TYPE_MKDIR_REQUEST：

~~~text
caData[0..31] = 新目录名称
caMsg[]       = 当前目录路径
~~~

服务端拼接当前目录和新目录名称，调用 QDir::mkdir 创建目录。

响应类型为 ENUM_MSG_TYPE_MKDIR_RESPOND，caData 中保存 bool 创建结果。成功后客户端提示成功并刷新当前目录，失败时提示创建失败。

### 7.8 删除文件或目录

客户端流程：

1. 选择文件或目录；
2. 弹出确认框；
3. 用户确认后拼接完整路径；
4. 从 m_fileInfoList 读取文件类型；
5. 创建 ENUM_MSG_TYPE_DELFILE_REQUEST；
6. 将文件类型写入 caData；
7. 将完整路径写入 caMsg；
8. 发送请求。

请求结构：

~~~text
caData[0..3] = 文件类型
caMsg[]      = 文件或目录完整路径
~~~

类型值：

~~~text
0 = 目录
1 = 普通文件
~~~

服务端普通文件调用 QFile::remove，目录调用 QDir::removeRecursively。

删除成功后，服务端根据当前用户和相对路径清理相关分享链接。

响应类型为 ENUM_MSG_TYPE_DELFILE_RESPOND。删除成功后客户端提示并刷新当前目录，失败时提示删除失败。

### 7.9 重命名文件或目录

客户端流程：

1. 选择文件或目录；
2. 输入新名称；
3. 新旧名称相同时结束；
4. 校验新名称；
5. 读取原条目类型；
6. 创建 ENUM_MSG_TYPE_RENAMEFILE_REQUEST；
7. 写入旧名称、新名称、类型和当前目录；
8. 发送请求。

请求结构：

~~~text
caData[0..31]   旧文件名
caData[32..63]  新文件名
caMsg 前 sizeof(uint) 字节：文件类型
caMsg 其余内容：当前目录路径
~~~

服务端拼接旧路径和新路径。目录使用 QDir::rename，普通文件使用 QFile::rename。

重命名成功后，服务端同步更新相关分享链接的相对路径。目录重命名时，目录下的链接路径整体平移。

响应类型为 ENUM_MSG_TYPE_RENAMEFILE_RESPOND。成功后客户端提示并刷新当前目录，失败时提示重命名失败。

### 7.10 文件管理基础操作时序

刷新列表：

~~~text
进入文件页面
 │
 ├── Client 读取 m_strCurPath
 ├── Client 发送 FLUSHFILE_REQUEST
 ├── Server 读取目录
 ├── Server 生成 FileInfo 列表
 ├── Server 返回 FLUSHFILE_RESPOND
 └── Client 更新文件列表
~~~

创建目录：

~~~text
输入目录名
 │
 ├── Client 校验名称
 ├── Client 发送 MKDIR_REQUEST
 ├── Server 创建目录
 ├── Server 返回结果
 └── Client 成功后刷新列表
~~~

删除文件：

~~~text
选择文件并确认
 │
 ├── Client 发送 DELFILE_REQUEST
 ├── Server 删除文件
 ├── Server 清理关联分享链接
 ├── Server 返回结果
 └── Client 成功后刷新列表
~~~

重命名文件：

~~~text
输入新名称
 │
 ├── Client 校验名称
 ├── Client 发送 RENAMEFILE_REQUEST
 ├── Server 执行重命名
 ├── Server 更新分享链接路径
 ├── Server 返回结果
 └── Client 成功后刷新列表
~~~

### 7.11 文件管理业务风险

1. 刷新、创建、切换、删除和重命名请求都携带客户端路径，服务端没有在所有基础操作中统一限制路径必须位于当前用户目录；
2. 部分操作没有统一校验当前连接是否已登录，可能绕过正常文件界面流程；
3. 删除目录使用递归删除，误操作可能删除整个目录树；
4. 删除、重命名等操作只返回布尔值，客户端无法区分文件不存在、名称冲突和权限失败；
5. 文件列表只有名称和类型，用户无法查看大小、修改时间和版本；
6. 快速切换目录或连续刷新时，旧响应可能覆盖新目录的显示结果；
7. 手动输入路径容易使用户进入错误目录，当前缺少目录树和面包屑导航；
8. 文件删除后没有回收站和恢复机制；
9. 当前双击普通文件没有打开、预览或下载行为；
10. 大量文件刷新返回完整目录快照，目录规模增大后操作体验会下降；
11. 文件名规则主要在客户端校验，服务端仍可能收到未经界面校验的非法名称；
12. 分享链接同步失败时，文件操作结果和分享链接状态可能不一致。

## 8. 业务功能六：文件上传

### 8.1 业务目标

将用户本地文件上传到当前用户云盘目录，支持大文件分块传输和中断后继续上传。

### 8.2 完整业务流程

1. 用户选择本地文件和云盘目标目录。
2. 客户端检查文件是否存在并读取文件大小。
3. 客户端向服务端发起上传初始化。
4. 服务端确认用户身份、目标目录和文件名合法。
5. 服务端检查目标位置是否已有同名文件，并确定本次上传的起始位置。
6. 客户端从起始位置读取文件数据并分块发送。
7. 服务端按顺序写入用户云盘文件。
8. 服务端返回下一次应上传的位置和是否完成。
9. 客户端继续发送剩余数据，直到文件全部写入。
10. 上传完成后客户端提示成功并刷新目标目录。

### 8.3 成功和失败流程

- 成功：文件完整写入目标目录，客户端刷新列表。
- 目录不存在、文件名非法、用户未登录或空间不足：上传失败。
- 网络中断：保留已写入内容，下次可从已完成位置继续上传。
- 写入失败或数据位置异常：停止本次上传并提示失败。

### 8.4 当前业务风险

1. 上传文件名和目标路径需要由服务端再次校验，不能只依赖客户端。
2. 上传中断时临时文件和最终文件的状态区分不够明确。
3. 同名文件的覆盖、跳过或自动改名规则需要统一。
4. 多个客户端同时上传同一路径时可能互相覆盖。
5. 客户端断线后无法立即知道服务端已写入的最终位置。

### 8.5 可扩展功能

1. 增加上传进度、速度和剩余时间。
2. 增加上传任务暂停、继续和取消。
3. 支持批量上传和后台上传。
4. 增加文件校验和，确认上传内容完整。
5. 增加上传失败自动重试。
6. 明确同名文件覆盖、跳过和自动改名选项。

## 9. 业务功能七：文件下载

### 9.1 业务目标

将云盘中的普通文件分块传输到用户本地，并在传输完成后生成完整的本地文件。

### 9.2 完整业务流程

1. 用户在云盘文件列表中选择普通文件。
2. 用户选择本地保存位置。
3. 客户端向服务端发起下载请求。
4. 服务端确认文件属于当前用户且文件可以读取。
5. 服务端打开文件并获取文件大小。
6. 服务端按固定大小读取文件数据。
7. 服务端连续发送文件数据块。
8. 客户端按顺序接收数据并写入本地文件。
9. 服务端发送完成标记。
10. 客户端关闭本地文件并提示下载完成。

### 9.3 成功和失败流程

- 成功：本地文件完整生成，客户端提示下载完成。
- 未选择文件、文件不存在或路径越权：不开始下载。
- 服务端读取失败、客户端写入失败或网络中断：下载失败并清理不完整结果。
- 服务端关闭连接时释放正在进行的下载资源。

### 9.4 当前业务风险

1. 下载路径和文件归属需要始终由服务端校验。
2. 当前缺少下载进度和剩余时间反馈。
3. 网络中断后不能稳定地从中断位置继续下载。
4. 多个下载任务同时进行时，客户端任务状态管理不够清晰。
5. 本地同名文件的覆盖规则需要明确。

### 9.5 可扩展功能

1. 增加下载进度、速度和剩余时间。
2. 支持暂停、继续和断点下载。
3. 支持批量下载和文件夹打包下载。
4. 增加本地文件完整性校验。
5. 增加下载队列和失败重试。

## 10. 业务功能八：移动文件

### 10.1 业务目标

将用户云盘中的文件或文件夹移动到自己的其他目录，并同步维护相关分享路径。

### 10.2 完整业务流程

1. 用户选择一个文件或文件夹并点击移动。
2. 客户端打开目录选择窗口。
3. 用户浏览自己的目录并选择目标目录。
4. 客户端提交源路径和目标目录。
5. 服务端校验源对象和目标目录都属于当前用户。
6. 服务端拒绝将文件夹移动到自身或子目录。
7. 目标目录存在同名对象时自动生成不重复名称。
8. 服务端优先执行直接移动，失败时尝试复制后删除源文件。
9. 移动成功后更新相关分享链接路径。
10. 客户端提示成功并刷新当前目录。

### 10.3 成功和失败流程

- 成功：源位置移除对象，目标目录出现对象，相关分享路径同步更新。
- 源文件不存在、目标目录不存在或路径越权：移动失败。
- 移动到自身或子目录：服务端拒绝。
- 文件复制成功但源文件删除失败：清理目标文件并判定失败。

### 10.4 当前业务风险

1. 自动重命名后的最终名称提示不够明确。
2. 大文件移动没有进度反馈。
3. 文件移动成功但分享路径更新失败时，可能出现状态不一致。
4. 多个客户端同时移动、删除或重命名同一对象时缺少并发控制。
5. 当前没有移动历史和撤销能力。

### 10.5 可扩展功能

1. 支持批量移动。
2. 增加移动进度和后台任务。
3. 提供覆盖、跳过、自动改名和逐个确认选项。
4. 增加移动撤销和操作历史。
5. 增加文件锁和空间检查。

## 11. 业务功能九：好友文件分享

### 11.1 业务目标

用户可以将云盘中的普通文件发送给一个或多个好友，好友同意后获得文件副本。

### 11.2 完整业务流程

1. 用户选择一个普通文件。
2. 客户端打开好友选择窗口。
3. 用户选择一个或多个好友并确认分享。
4. 服务端检查文件归属和分享对象。
5. 服务端向在线好友转发分享申请。
6. 好友收到提示并选择同意或拒绝。
7. 好友同意后，服务端将源文件复制到接收方用户目录。
8. 目标目录存在同名文件时按当前规则处理重名。
9. 服务端返回复制结果。
10. 接收方客户端提示结果并刷新文件列表。

### 11.3 成功和失败流程

- 成功：接收方获得文件副本，发送方原文件保持不变。
- 选择文件夹：当前不允许分享。
- 好友离线：当前不能实时收到分享申请。
- 好友拒绝、源文件不存在或复制失败：分享未完成。

### 11.4 当前业务风险

1. 服务端需要确认发送人是当前登录用户，并确认文件属于发送人目录。
2. 好友离线时申请不能及时送达。
3. 好友拒绝后发送方没有明确结果通知。
4. 复制失败只有简单成功或失败结果，缺少具体原因。
5. 大文件复制没有进度反馈。
6. 接收方不能选择保存目录，且同名处理规则需要明确。

### 11.5 可扩展功能

1. 支持离线分享申请和待处理通知。
2. 增加分享进度和批量结果。
3. 支持接收方选择保存目录。
4. 增加分享记录、撤回和有效期。
5. 支持文件夹分享和权限控制。

## 12. 业务功能十：分享链接管理

### 12.1 业务目标

用户可以为普通文件生成外部分享链接，其他用户通过链接将文件复制到自己的云盘“分享链接”目录。

### 12.2 完整业务流程

1. 用户选择一个普通文件并生成分享链接。
2. 服务端生成随机令牌，并保存令牌加密值。
3. 服务端记录文件所有者、文件路径、有效期和撤销状态。
4. 客户端显示并允许用户复制分享链接。
5. 接收方粘贴完整链接或令牌。
6. 服务端查询分享记录并检查链接是否存在、过期或撤销。
7. 服务端检查源文件仍存在且属于分享者目录。
8. 服务端在接收方目录创建“分享链接”文件夹。
9. 服务端将源文件复制到接收方目录，重名时自动改名。
10. 客户端提示获取结果并刷新文件列表。

当前链接默认有效期为 24 小时，只支持普通文件，不支持文件夹。

### 12.3 成功和失败流程

- 成功：接收方获得文件副本，分享者原文件不受影响。
- 文件夹、空链接或无效链接：客户端拒绝或提示失败。
- 链接过期、已撤销、源文件被删除或复制失败：无法获取文件。

### 12.4 当前业务风险

1. 服务端需要确认分享路径属于当前登录用户。
2. 查询已有链接时，客户端提供的文件所有者信息需要由服务端重新确认。
3. 当前有效期固定，不能自定义期限。
4. 缺少完整的链接撤销入口和访问记录。
5. 获取大文件没有进度反馈。
6. 接收文件固定保存到“分享链接”目录。

### 12.5 可扩展功能

1. 支持自定义有效期、访问密码和访问次数。
2. 增加分享链接管理、撤销和失效提醒。
3. 支持文件夹分享和接收方自选目录。
4. 增加访问日志、二维码和批量管理。
5. 增加分享文件去重和来源标记。

## 13. 业务功能十一：心跳与在线状态

### 13.1 业务目标

通过定时心跳确认客户端和服务端连接正常，及时发现失效连接，并维护好友列表中的在线状态。

### 13.2 完整业务流程

1. 用户登录成功后，服务端将用户状态设置为在线。
2. 客户端每 30 秒发送一次心跳。
3. 服务端收到心跳后更新连接最后活动时间并返回确认。
4. 客户端收到确认后更新最近响应时间。
5. 服务端每 30 秒扫描连接活动状态。
6. 超过 90 秒没有活动的连接被判定为失效。
7. 服务端关闭失效连接并执行下线处理。
8. 服务端将用户状态设置为离线，并移除该连接。
9. 客户端长时间收不到确认时弹出重连窗口。
10. 用户发起重连后重新建立连接。

### 13.3 成功和失败流程

- 成功：持续收到心跳确认，用户保持在线。
- 客户端停止发送或服务端无响应：连接超时并进入重连流程。
- 网络断开：服务端清理连接并将用户设为离线。
- 重连失败：用户保持离线，直到重新连接成功。

### 13.4 当前业务风险

1. 多设备登录时单个在线字段可能被不同连接互相覆盖。
2. 某个连接断开时，可能错误影响同一用户其他连接的在线状态。
3. 网络短暂波动期间，在线状态可能延迟更新。
4. 重连期间正在进行的上传、下载或聊天操作可能中断。
5. 重连成功后需要确保登录身份和业务状态正确恢复。

### 13.5 可扩展功能

1. 使用独立会话记录支持多设备在线。
2. 增加最后在线时间和离线时长。
3. 增加自动重连次数和间隔策略。
4. 重连成功后恢复登录状态及未完成传输任务。
5. 区分正常退出、网络断开、心跳超时和服务端故障。

## 14. 业务功能十二：用户注销

### 14.1 业务目标

用户确认密码后永久删除账户及其相关数据。该功能不是退出登录，操作不可恢复。

### 14.2 完整业务流程

1. 用户点击注销账户。
2. 客户端要求输入当前账户密码。
3. 客户端弹出永久删除的二次确认。
4. 用户确认后提交注销操作。
5. 服务端验证用户名和密码。
6. 验证成功后删除聊天记录和好友关系。
7. 删除该用户创建的分享链接及相关账户记录。
8. 提交数据库事务。
9. 删除该用户的云盘目录。
10. 服务端返回注销结果。
11. 客户端注销成功后清理登录状态，关闭主界面并返回登录界面。

### 14.3 成功和失败流程

- 成功：账户、关联关系和用户云盘目录被删除，用户返回登录界面。
- 用户取消密码输入或二次确认：不执行注销。
- 密码错误、用户不存在或数据库处理失败：保留账户和文件。
- 数据库删除成功但目录删除失败：账户可能已删除，但文件目录可能残留。
- 网络中断：客户端无法立即确认最终注销结果。

### 14.4 当前业务风险

1. 服务端需要确认注销用户名与当前登录连接身份一致。
2. 操作不可恢复，误操作会永久删除账户和文件。
3. 数据库删除成功但云盘目录删除失败时可能残留文件。
4. 注销时存在上传、下载任务可能产生临时文件。
5. 多设备登录时注销一个连接可能影响其他连接的在线状态。
6. 其他用户已经复制的分享文件不会随原账户删除。

### 14.5 可扩展功能

1. 增加注销冷静期和账户恢复能力。
2. 注销前显示数据统计和删除清单。
3. 支持导出聊天记录和云盘文件。
4. 增加后台清理任务和文件残留检查。
5. 注销后强制所有设备下线。
6. 增加注销操作日志和管理员恢复流程。

 ├── Client.m_LoginName = 用户名
