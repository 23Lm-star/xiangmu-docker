# QT 云盘聊天系统融合式扩展功能路线图

> 状态：规划文档
>
> 来源：`项目扩展前景.md`、`业务功能文档.md` 的全部“业务扩展/可扩展功能”项。
>
> 边界：本文只描述后续扩展，不将规划能力表述为当前已实现。当前上传基线是单文件、顺序 ACK 分块上传与服务端线程池异步写盘；多文件并行和单文件乱序并行分片均属于规划能力。

## 1. 目标与融合原则

项目不应演进为“聊天、上传、分享”各自维护状态的功能集合，而应演进为一个轻量协作云盘：用户通过安全会话进入系统，在统一文件资产模型上完成传输、分享、协作和沟通，所有关键操作均可恢复、审计和治理。

```text
安全身份与会话
        │
        ├── 社交协作：好友、群组、消息、通知
        │
        ├── 文件资产：目录、引用、权限
        │       ├── 传输任务：上传、下载、暂停、恢复、校验
        │       └── 分发能力：好友分享、协作目录、外链
        │
        └── 平台治理：审计、配额、清理、缓存、服务拆分
```

融合规则：

1. 任何业务请求都先经过 `sessionId/sessionVersion` 鉴权，不能信任客户端传入的用户名、所有者或路径。
2. 物理文件内容与用户看到的文件条目分离；秒传、分享、外链和协作目录不再各自复制文件。
3. 上传、下载、复制、打包均统一为可持久化任务；重连后由会话和任务状态恢复，而不是仅重建 TCP 连接。
4. 私聊、群聊、分享通知和系统通知共用带唯一 ID、投递状态和多端同步能力的消息模型。
5. 删除、重命名、移动、撤销分享和账户注销由领域服务统一联动元数据、权限、引用计数、通知和审计，禁止仅靠路径字符串在多个处理函数中修补。

## 2. 统一基础模型

### 2.1 身份、会话与访问控制

```text
user                 用户账号、密码哈希、状态
user_session         session_id、session_version、设备、连接、最近活跃、状态
device               设备名称、登录时间、最后在线时间
friend_request       申请人、接收人、状态、申请/处理时间
friend_relation      好友备注、分组、标签、黑名单、隐私设置
group_info           群组名称、创建人、公告、状态
group_member         group_id、user_id、角色(owner/admin/member)、禁言状态
```

- 密码改为 PBKDF2、bcrypt 或 Argon2 的带盐哈希；数据库连接凭据由受保护配置或环境变量提供。
- `sessionVersion` 是唯一有效会话的最终校验。新设备登录时递增版本、通知并关闭旧连接；旧连接即使未立即断开，也不能继续调用聊天、文件或心跳接口。
- 传输层升级 TLS 后，登录、消息、外链令牌和文件控制指令均不以明文暴露。
- 好友、群成员、目录权限和外链策略最终统一为服务端访问控制决策，不由客户端界面决定。

### 2.2 文件资产、目录与权限

```text
file_object          object_id、content_hash、physical_path、size、ref_count
user_file            file_id、owner_id、object_id、parent_id、display_name、deleted_at
file_permission      file_id、subject(user/group/link)、role(owner/editor/viewer)、expire_at
share_link           link_id、file_id、owner_id、link_token、created_at
```

- `file_object` 代表物理内容，内容哈希唯一；`user_file` 代表用户目录中的逻辑条目。
- 秒传只新增 `user_file` 引用，好友分享、链接领取和协作目录也只新增引用和权限。
- 收藏、置顶、标签、备注、最近使用和目录树均依附于 `user_file`；物理内容在 `ref_count` 归零后异步清理。
- 文件锁用于编辑、重命名、移动和批量操作冲突控制；锁与权限判断均以 `file_id` 为键，避免路径迁移后状态失效。

### 2.3 传输任务与分片会话

```text
transfer_task        task_id、user_id、direction、file_id/session_id、状态、优先级、进度
upload_session       session_id、task_id、temp_path、file_size、file_hash、状态、updated_at
upload_chunk         session_id、chunk_index、offset、length、chunk_hash、状态
download_session     session_id、task_id、target_path、received_size、状态
```

- `UploadTaskManager` 维护等待、运行、暂停、失败、完成五类任务，限制最大并发数，并展示单任务和总任务的进度、速率、剩余时间。
- 每个上传/下载请求与 ACK 必须携带 `taskId/sessionId`，使一个连接可安全复用多任务；失败重试、暂停、恢复、取消和后台上传均以持久化任务状态为依据。
- 初期保持顺序 ACK：`UPLOAD_CHUNK(sessionId, offset, data)`，服务端返回下一确认位置。
- 高级阶段支持单文件多分片并行：`sessionId + chunkIndex + chunkOffset + chunkLength + chunkHash`。服务端预分配临时文件、记录完成位图，以 `sessionId + chunkIndex` 幂等去重；全量 SHA-256 校验通过后原子重命名为正式文件。
- 动态分片尺寸由初始化响应下发 `recommendedChunkSize/maxInFlightChunks`，在 4 KB 到 1 MB 的受控区间内依据 ACK 延迟、写缓冲高水位和重传情况调整。

### 2.4 消息、通知与审计

```text
message              message_id、conversation_id、sender、type、payload_ref、created_at
message_delivery     message_id、recipient、device、state(sent/delivered/read/failed)
conversation         private/group/system、last_message_id、retention_policy
notification         user_id、type、payload_ref、read_at
audit_log            actor、action、resource_type、resource_id、result、trace_id
```

- 当前扩展只保留文本私聊和群聊，不扩展图片、语音、视频、表情等富媒体消息。
- `message_id` 与投递状态支持发送方回显、失败重试、已送达、已读、未读数量、离线补偿和多设备去重同步。
- 好友申请、分享申请、分享撤销、群邀请、会话失效、任务完成和账户恢复均进入统一通知中心。
- 文件、分享、权限、登录、注销、管理员恢复等敏感操作进入审计日志，支撑用户可见操作历史和后台排障。

## 3. 融合后的业务能力

### 3.1 社交关系与协作入口

好友模块仍提供好友申请、处理、黑名单和在线状态；群聊扩展只围绕用户已筛选的核心能力展开，并与好友关系复用成员和通知机制。

### 3.2 群组生命周期与成员权限

群聊采用“创建、入群、管理、解散”的完整生命周期：

1. 用户创建群聊。服务端先检查登录状态和创建频率限制，再创建 `group_info`，将创建者写入 `group_member` 并设为群主。
2. 创建者选择好友发起入群申请/邀请。两者视为同一条入群流程：被邀请好友同意后入群，拒绝则不建立成员关系；离线用户登录后处理待办。
3. 群主或管理员可以查看、搜索群成员；群主可以任命或撤销管理员，群主可以转让群主身份。
4. 群主和管理员可以禁言成员或开启全员禁言；服务端在发送消息前统一校验角色和禁言状态。
5. 成员可以主动退出，群主或管理员可以移除成员；入群、退群和被移除均发送群通知。
6. 群主可以修改群名称和群公告。公告发布后向成员发送通知并在群资料中展示。
7. 群主解散群聊前执行解散策略：停止新消息和新文件操作，通知全体成员，保留或清理历史数据按预设规则处理。

### 3.3 可靠群消息

群消息只扩展文本消息，复用 `conversation/message/message_delivery`：

1. 客户端提交 `groupId、messageId、senderId、content`；服务端校验会话、成员身份、禁言状态和消息发送频率。
2. 服务端保存消息后返回“发送确认”。该状态表示消息已被服务端接收并持久化，用于区分发送失败，但不代表其他成员收到。
3. 服务端向在线成员实时分发；客户端收到后记录“已送达”；成员打开群聊并确认阅读后记录“已读”。
4. 离线成员的消息保存在服务端，上线后按时间拉取；客户端支持历史分页和未读数量。
5. ACK 丢失或网络异常时，客户端按 `messageId` 重试；服务端按唯一 ID 幂等处理，避免重复消息。
6. 群成员可以使用 `@指定成员` 或 `@全体成员` 触发定向通知；群消息和成员事件通过统一通知机制推送。
7. 支持多设备同步，使用 `messageId + device` 记录各设备投递状态。

### 3.4 群消息操作

在权限和时间窗口允许的范围内，成员可以撤回、引用回复、转发、收藏、编辑或删除自己的群消息；群主和管理员可按管理规则删除违规消息。所有操作都必须经过服务端成员权限校验，并向相关成员同步结果。

### 3.5 群文件与协作目录

群文件使用现有上传、下载和任务机制：成员根据群文件权限上传或下载文件，服务端复用文件归属校验、分块传输、任务进度和失败重试。群协作目录将目录访问权限授予群组，成员在权限范围内查看和操作共享文件。

### 3.6 群通知、清理与治理

群成员变化、群公告、群消息、任务结果和解散事件统一进入通知中心。系统提供群消息清理策略，按群主配置或系统规则清理历史数据；同时限制群创建频率和群消息发送频率，防止滥用。群操作审计保留创建、成员变更、权限变更、公告、消息管理和解散等关键事件。

### 3.3 文件工作区与协作目录

用户文件区在基础目录操作之上扩展：面包屑、目录树、文件名/大小/类型/修改时间排序、搜索、分页、增量刷新、元数据显示、批量选择、批量删除、批量重命名、拖拽上传、拖拽移动、最近使用、常用目录、收藏、置顶、标签和备注。

协作目录将 `file_permission` 授权给用户或群组，提供 owner/editor/viewer 权限、文件锁、空间检查和冲突策略。批量移动、覆盖/跳过/自动改名/逐项确认、文件夹打包下载都由后台传输任务执行，避免阻塞 UI 或 Socket 事件循环。

### 3.4 统一上传下载任务中心

上传扩展包括：进度、速度、剩余时间、暂停、恢复、取消、失败重试、同名覆盖/跳过/自动改名、批量与后台上传、完整性校验、多文件有限并发、可恢复会话、动态分片和单文件并行分片。

下载使用同一任务框架：进度、速率、剩余时间、暂停、恢复、断点下载、批量下载、失败重试、本地哈希校验、文件夹打包下载和本地同名冲突策略。控制连接上的心跳和消息优先级高于数据流；大文件传输受 `bytesToWrite()` 高水位和限速约束，避免阻塞 PONG 或普通消息。

文件秒传是传输中心与文件资产的交点：客户端先提交内容哈希，若 `file_object` 已存在并且用户有创建条目的权限，直接创建引用；未命中才创建 `upload_session`。服务器必须在完整上传后自行计算哈希，不能仅信任客户端摘要。

### 3.5 分享链接与好友分享

好友分享和普通链接分享共用文件权限模型：

- 好友/群分享支持离线待处理、接收方自选目录、批量结果、进度、撤回、文件夹和权限控制；
- 分享者选择文件后生成普通链接，服务端保存链接与文件的对应关系；接收方粘贴完整链接，服务端校验链接有效性和文件访问权限后，将文件复制或创建逻辑引用到接收方目录；
- 链接功能只保留生成、复制、粘贴、校验和获取文件的基本闭环，不扩展提取密码、访问次数、二维码、复杂外链管理或独立 HTTP 下载页；
- 文件移动、重命名、删除和账户注销时，服务端按文件归属同步处理关联链接，避免链接指向无权限文件。

### 3.6 在线状态、重连和账户生命周期

心跳负责存活检测，独立会话记录负责准确在线状态。系统区分正常退出、网络断开、心跳超时和服务端故障，记录最后在线时间与离线时长；自动重连采用指数退避，成功后使用安全会话恢复消息订阅和未完成传输任务。

账户注销扩展为受控生命周期：注销前显示数据统计与删除清单，允许导出聊天记录和云盘文件；进入冷静期后可恢复，过期后由后台任务执行清理。执行时撤销会话、停止传输任务、处理分享授权、保留必要审计记录并检查文件残留；管理员恢复仅在明确授权和审计下进行。

## 4. 端到端融合流程

### 4.1 大文件上传后分享给群组

```text
登录 -> session 校验 -> 创建 transfer_task/upload_session
     -> 秒传命中：直接创建 user_file 引用
     -> 未命中：动态分片上传 -> 分片幂等 ACK -> 全量哈希校验 -> file_object 转正
     -> 创建 user_file/审计记录
     -> 授权给 group_id -> 生成群通知和可选群消息
     -> 成员按权限看到逻辑条目；编辑时写时复制
```

这一条流程将多文件队列、并行分片、秒传、群组、通知、权限和审计连接在同一份状态模型中。

### 4.2 外链领取与后续治理

```text
创建者选择 file_id -> 服务端验证 owner 权限 -> 写 share_link(token hash/策略)
  -> 接收方粘贴普通链接 -> 服务端校验链接与权限
  -> 创建接收者 user_file 引用或文件副本 + 来源记录
  -> 创建者撤销链接：禁止未来领取，并通知相关用户
  -> 原文件移动/改名：按文件归属同步链接关系
  -> 原文件删除：链接失效，禁止继续获取
```

### 4.3 断网后的恢复

```text
心跳超时 -> 自动重连（指数退避） -> session 恢复/校验版本
  -> 拉取未投递消息与通知 -> 读取 transfer_task/upload_session
  -> 已完成分片跳过，未确认分片按 taskId/sessionId 重试
  -> 下载从本地确认位置续传 -> UI 恢复进度与失败提示
```

## 5. 协议与服务演进

继续使用现有长度前缀自定义 PDU、`caData[64]` 和 `caMsg` 结构，不更换为 Protobuf/JSON，也不重新设计报文头。新增业务只在现有枚举和字段约定上向后兼容地追加消息类型；`taskId/sessionId` 等任务字段按具体消息的现有载荷空间承载，必要时通过 `caMsg` 扩展。

服务端先在单体内按领域职责整理 `SessionService`、`FileCatalogService`、`TransferService`、`MessageService`、`ShareService` 和 `NotificationService`，但不改变客户端与服务端之间的 PDU 通信方式。只有在压测证明单体文件 IO 或连接路由成为瓶颈后，才考虑独立文件服务；Redis 仅作为热点缓存和限流加速，MySQL 仍保存最终事实。

Redis 仅用于在线状态、会话缓存、好友/群成员热点校验、限流和任务调度加速；MySQL 仍保存用户、文件、权限、消息、任务和审计的最终事实，不能将一致性完全交给缓存。

## 6. 一级扩展模块总览

以下按完整业务模块归类；括号内是该模块覆盖的子能力，子能力不单独作为一级功能。

| 一级扩展模块 | 覆盖范围 | 与其他模块的融合点 |
|---|---|---|
| **账号、会话与安全** | 密码加盐哈希、TLS、受保护配置、设备管理、唯一有效会话、自动重连、心跳、在线/离线/最后在线、故障分类 | 为好友、群聊、文件、外链和注销提供统一鉴权；会话恢复传输任务和消息状态 |
| **好友关系与通知** | 离线好友申请、同意/拒绝/忽略/撤回、备注、分组、标签、黑名单、隐私、资料、搜索、排序、批量管理、推荐、共同好友、申请/分享/任务通知 | 好友关系决定私聊、好友分享和群邀请；通知中心统一承载未处理申请、分享和系统事件 |
| **群组协作** | 创建群、邀请/退出/踢人、成员列表、群主/管理员/成员角色、禁言、群公告、群权限、群聊、群文件、群目录 | 群既是消息会话，也是文件权限主体和批量分享对象 |
| **可靠私聊与群聊** | 消息 ID、发送确认、已送达、已读、失败重试、未读、离线补偿、多端同步、历史分页/搜索、导出备份恢复、保留策略、免打扰/举报 | 好友、群组和通知共享消息投递模型；不扩展富媒体消息 |
| **文件工作区与协作目录** | 目录树、面包屑、排序、搜索、分页/增量刷新、元数据、批量操作、拖拽、收藏、置顶、标签、备注、最近使用、常用目录、目录权限、文件锁、重名冲突、空间检查、移动撤销、文件夹打包 | 以 `user_file` 为用户视图；权限主体可以是用户、群组或普通分享链接 |
| **统一上传下载任务** | 上传/下载进度、速度、剩余时间、暂停、恢复、取消、后台任务、队列、失败重试、同名策略、校验、多文件有限并发、可恢复会话、动态分片、单文件并行分片、下载断点续传、批量传输、限速和配额 | `transfer_task` 与心跳/重连共享恢复状态；分片完成后提交文件资产并产生通知/审计 |
| **文件资产与内容寻址** | `file_object/user_file`、文件秒传、内容去重、引用计数、写时复制、物理对象异步回收、来源追踪 | 为分享、协作目录和存储清理提供统一物理内容模型；不扩展文件版本、回收站和文件操作记录 |
| **好友分享与普通链接分享** | 离线分享、进度、批量结果、接收方选目录、撤回、文件夹分享、权限控制、普通链接生成/复制/粘贴/校验/获取 | 通过 `file_permission + share_link` 授权；领取创建引用或文件副本，文件删除后链接失效；不扩展密码、访问次数、二维码和独立 HTTP 外链页 |
| **账户生命周期与运营治理** | 注销冷静期、恢复、删除清单、数据导出、强制下线、后台临时任务清理、管理员恢复、限流、配额、指标监控 | 注销统一处理 session、transfer、message、file、share，避免状态残留 |
| **平台架构演进** | 领域服务拆分、文件服务独立、对象存储、Redis 会话/在线状态/限流缓存、上传下载专用服务 | 保持现有自定义 PDU 不变；只有压测证明瓶颈后实施 |

## 7. 实施路线与依赖

| 阶段 | 交付重点 | 前置条件 | 主要收益 |
|---|---|---|---|
| P0 安全与状态基线 | 密码哈希、TLS、会话版本、服务端统一鉴权、操作审计 | 现有登录/心跳 | 消除用户名和单一 `online` 字段带来的越权与多端状态问题 |
| P1 任务化传输 | `transfer_task/upload_session`、暂停恢复取消、进度、下载续传、多文件有限并发 | P0 会话鉴权 | 任务可恢复，传输与重连、心跳不再割裂 |
| P2 文件资产层 | `file_object/user_file`、哈希校验、秒传、引用计数、基础权限 | P1 完整性校验 | 去重、分享和协作目录共用文件模型 |
| P3 协作与可靠消息 | 好友申请、通知中心、消息 ID/ACK、私聊/群聊、协作目录 | P0 会话、P2 权限与文件引用 | 聊天与文件分享形成协作闭环 |
| P4 分享与体验 | 引用式好友/群分享、普通链接分享、搜索、批量操作、文件夹打包 | P2 文件资产、P3 通知 | 统一获取文件体验，避免重复实现分享流程 |
| P5 吞吐与平台 | 动态分片、单文件并行分片、Redis、文件服务拆分 | P1 任务幂等、P2 元数据稳定 | 提升大文件和高并发能力，同时保持 PDU |
| P6 生命周期治理 | 注销冷静期、导出恢复、配额、限流、后台临时任务清理、管理员恢复 | P2 引用计数、P1 任务状态 | 可运营、可恢复、可清理 |

并行分片必须放在 P1 之后：当前连续 offset 的顺序 ACK 模型不能直接改成乱序上传。引用式分享必须放在 P2 之后：没有稳定的 `file_id/object_id`，分享和来源追踪仍会退化为脆弱的路径关联。

## 8. 验证重点与风险

1. 鉴权：旧会话、新会话、伪造 owner、跨用户路径、被拉黑用户和过期外链均必须被服务端拒绝。
2. 传输：重复分片、乱序分片、ACK 丢失、取消时在途写入、重连恢复、哈希不一致和临时文件超时清理均应可验证。
3. 文件：同一内容秒传、引用计数、写时复制、移动后链接和权限连续性必须正确。
4. 消息：同一 `message_id` 重试不会重复展示；发送确认、已送达、已读、离线和多端状态在最终一致性范围内可收敛。
5. 协作：群角色、协作目录权限、文件锁、分享撤回和账户注销在并发操作下不能遗留越权入口。
6. 性能：以吞吐、P95/P99 延迟、写缓冲、磁盘 IO、RSS、任务恢复成功率为指标；自研内存池与 Redis/并行分片都必须用压测数据证明收益。

## 9. 面试表述边界

可表述为：项目当前已具备自定义 TCP PDU、半包粘包处理、单文件顺序 ACK 分块上传、服务端异步写盘、流式下载、心跳、好友聊天和基础分享；后续扩展按本文路线将其升级为具备会话安全、可恢复任务、内容寻址文件资产和群组协作能力的协作云盘。

不可将多文件并行上传、单文件乱序并行分片、文件秒传、引用式分享、TLS、Redis、微服务化或完整群聊表述为已经完成，除非对应代码、迁移脚本和验证证据已实际落地；现有自定义 PDU 不作为替换项。
