# 需求范围与验收标准

> 生成依据：`Client/` 和 `Server/` 代码实现、`docs/agent.md`、`docs/PROJECT_IMPLEMENTATION.md`
> 状态：初版（v1），基于已实现功能反向整理

---

## 1. 系统概述

基于 Qt/C++ 的客户端-服务端文件管理与即时聊天系统。客户端提供用户注册登录、好友管理、一对一聊天、文件浏览/上传/下载/分享功能；服务端基于 TCP 提供并发连接处理、消息路由、文件存储和 MySQL 数据持久化。

## 2. 功能需求

### 2.1 用户认证

| 编号 | 功能 | 已实现 | 验收标准 |
|------|------|--------|----------|
| AUTH-01 | 用户注册 | ✅ | 输入用户名+密码+验证码，通过后可注册；用户名仅含数字和大小写字母，长度≤31 |
| AUTH-02 | 用户登录 | ✅ | 输入用户名+密码+验证码，验证通过后进入主界面；错误提示明确 |
| AUTH-03 | 验证码 | ✅ | 服务端生成6位随机码，客户端请求后显示；有效期60秒；同一号码冷却期内不可重复获取 |
| AUTH-04 | 用户下线 | ✅ | 关闭连接时服务端自动将用户在线状态置为 0 |

| FRD-03 | 添加好友 | ✅ | 发送好友请求→目标用户确认→双向好友关系建立 |
| FRD-04 | 刷新好友列表 | ✅ | 获取当前用户的所有好友 |
| FRD-05 | 删除好友 | ✅ | 解除双向好友关系 |

### 2.5 连接健康

| 编号 | 功能 | 状态 | 验收标准 |
|------|------|------|----------|
| NET-01 | 客户端应用层心跳 | 规划中 | 登录后由唯一心跳组件每 30 秒发送 PING；服务端返回 PONG；连续 3 次未确认时才中止连接并复用既有断开清理，不影响文件、好友、聊天和认证业务。 |

## 4. 边界与限制

| 限制项 | 说明 |
|--------|------|
| 最大并发客户端 | 依赖 QThreadPool（当前 max=8），但 socket I/O 实际在事件循环线程处理 |
| 最大聊天消息长度 | 受 PDU 总长度限制（`uint`），通常无硬限制但柔性数组分配依赖堆内存 |
| 用户名长度 | ≤31 字节（UTF-8） |
| 密码方案 | 客户端 MD5 哈希后传输；服务端存储 MD5 值，无盐 |
| 文件上传分块 | 4096 字节 |
| 内存池最大对象 | 256 KB（超过则直接走 PageCache 按页分配） |

## 6. 验收准则（质量门禁）

初步设定以下必须通过的验收点：

1. 客户端可成功连接服务端并完成注册/登录流程
2. 好友添加、聊天发送接收、离线消息可达
3. 文件上传（含断点续传）、下载、删除、重命名、分享功能正常
4. 服务端多客户端并发不崩溃
5. 数据库连接池在多线程下不泄漏连接
6. 已知的阻塞/严重缺陷已修复或已接受风险
