# REQ-EXT-SHARE-001 外链分享生命周期（重新生成 / 续期）— 任务记录

## 档位
**MEDIUM**。理由：
- **公共契约变更（可选复核覆盖层：契约）**：两端 `protocol.h`（manifest `sensitive_paths`）追加常量块，
  52 请求 caMsg 追加动作区、53/57 响应 caData 追加状态字——是**仅追加、双向向后兼容**的变更，不是破坏性契约。
- **数据面（可选复核覆盖层：数据）**：新增一条 UPDATE（续期）与一条 DELETE（重新生成作废旧行），
  作用域限于 `share_link` 中单个 owner+path 的行，失败可回滚。
- 不是 LARGE：无破坏性迁移、无安全/系统边界变更、回滚=revert 本提交、爆炸半径限于外链分享一个功能面。
- 敏感路径命中（protocol.h ×2）按 v1.7 规则只产生审查 finding，不单独决定档位。

## 来源
2026-10-12 全功能审计缺陷 ②，主人复验补充语义：
> 现在通过分享链接获取文件显示"分享链接已失效"。我想要的语义是可以有选择：
> 第一种是可以重新获取链接的选项，第二种是可以续期的选项（续期时长可以自己设计）。

## 现状（缺陷 ②）
`MsgHandler::createPublishLink` 命中 `getShareLinkByPath` 就直接回存库 hash，
既不校验也不刷新 `expire_time`，也不看 `revoked`。于是链接一过 24h 有效期，
「生成/获取分享链接」永远返回同一条死链，解析必失败，主人没有任何自助恢复手段。

## 交付
1. **零新报文**：动作走 52 请求 caMsg 首个 NUL 之后的附加区（`<action>\0<seconds>`），
   状态走 53/57 响应 `caData[8..11]`。旧服务端 `fixedString` 读到首个 NUL 即止 → 忽略附加区；
   旧客户端不读该区间、`mkPDU` 全零初始化 → 读到 0=有效 → 语义与旧版一致。
2. 服务端按动作分派：
   - `new`：**先精确作废旧行**（旧链接立即失效）再生成新 token —— "重新获取"要能换掉已泄露的旧链接；
   - `renew`：只前推 `expire_time`、token 不变；**已撤销的行拒绝续期**（续期不能让作废链接复活）；
   - 缺省动作：旧语义（有记录复用、无则新建），但状态字回**真实状态**——过期时不再谎报有效。
3. 客户端：`获取/生成分享链接` 命中失效链接时弹三键框 ——
   「重新生成链接」/「续期」（7/30/90/365 天，缺省 30 天）/「取消」；已撤销时禁用续期按钮。
4. 新套件 `share001`（25 断言）注册进 `test_gate`（15 套 / 539 断言）。

## 不变式
- I1 续期不改 token；`new` 一定换 token 且旧 token 立即不可解析。
- I2 状态字三态互斥：有效(0)/过期(1)/撤销(2)；`state != VALID` ⇒ 该链接当前不可解析。
- I3 旧语义路径行为不变（除"状态字不再谎报有效"这一处修正）。
- I4 响应 caData[0]（`ok` / `exists`）语义与旧版逐字节相同。

## 验收
- 自动：`share001` 25/25（静态 2 + 动态 23），全量门禁 15 套 / 539 断言。
- **人工（GUI）**：右键「获取分享链接」→（把该行 `expire_time` 改成过去）→ 再获取 →
  应弹三键框；选「续期」→ 选 30 天 → 提示生成成功且该链接可解析；
  选「重新生成链接」→ 旧链接解析应失败、新链接成功。
