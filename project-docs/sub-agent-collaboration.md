# Hermes 子代理 (Sub-Agent) 协同规范

> 本文件定义了在本项目中，主 Agent 处理复杂任务时，应当如何运用分解思维，模拟或委托给专职子代理。本规范旨在减少上下文消耗、提高操作精准度。

在处理代码检索、文件分析、文档维护等任务时，主 Agent 应主动应用以下子代理的工作模式（通过调用对应的内置工具或 `delegate_task` 来实现）：

## 1. 代码搜索代理 (CodeSearchAgent)
- **目标**：通过静态代码搜索快速定位代码，避免大面积泛读。
- **触发场景**：需要查找某个函数调用、宏定义或特定字符串的分布时。
- **操作方式**：使用 `search_files` 工具，设定具体的 `search_pattern`、限制 `search_path` (如 `Client/` 或 `Server/`) 并使用正则表达式或文件名过滤。

## 2. 文件加载代理 (FileLoaderAgent)
- **目标**：精确加载大文件片段，避免一次性加载过多无用代码。
- **触发场景**：分析长文件 (`.cpp` 或 `.h`) 中的特定函数或类结构时。
- **操作方式**：使用 `read_file` 工具，通过指定 `offset` 和 `limit` 参数，实现分页或分块读取。

## 3. 文档维护代理 (DocMaintainerAgent)
- **目标**：对 `project-docs/` 下的文档进行结构化、原子化更新，不破坏原有格式。
- **触发场景**：需要记录 Bug 状态变更、追加审查记录或更新项目进度时。
- **操作方式**：使用 `patch` 工具执行精确的文本替换，或通过 `execute_code` 配合 Python 脚本执行基于 Markdown 结构的更新。

## 4. 报告生成代理 (ReportGeneratorAgent)
- **目标**：输出格式化的结构性内容，如测试报告或代码审查报告。
- **触发场景**：阶段性验证完成或进行综合评估时。
- **操作方式**：依照事先商定的模板（例如 Markdown 表格格式），将分散的数据组织成一致的报告结构并写入文档。

## 5. 交接构造代理 (HandoffBuilderAgent)
- **目标**：生成符合《协作总则》的标准化交接指令。
- **触发场景**：当前开发/测试环节结束，需要转交下一位（或下一次会话）处理时。
- **操作方式**：严格输出包含“缺陷状态变更列表”、“文件清单”以及“给下游的提示词”的交接区块。

## 6. 状态管理代理 (StatusManagerAgent)
- **目标**：维护工作流状态的合法性流转。
- **触发场景**：处理 Bug 报告的状态迁移（如“待测试”->“已修复”）。
- **操作方式**：修改状态前，必须先读取当前状态字段确认流转是否合法，并在变更后添加操作时间戳及原因。

---
**核心指导原则**：
不要一次性做完所有事。主 Agent 在接到宏大指令时，应当把自己的角色“降维”为各个专职的子代理，通过串联这几个专有模式（调用相应的底层 API 工具），安全、逐步地逼近目标。
